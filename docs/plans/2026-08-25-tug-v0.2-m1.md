# tug v0.2 «Halyard» — M1 «Bytes decode» (Phases 0–2) — Implementation Plan

> **To execute:** use the `executing-plans` skill. Steps use `- [ ]` for tracking.

**Goal:** `tug dev sse-dump < testdata/fixtures/anthropic/clean-turn.sse` prints a
clean event stream decoded from recorded bytes; every gate v0.2 needs before it is
allowed to open a socket exists and has failed once on purpose; and the wire
vocabulary the whole version speaks — `StreamEvent`, the error taxonomy, the
request types, the ndjson encoding — is defined and golden-tested before a single
consumer exists.

**Architecture:** three layers, bottom-up, none of which touches a socket. Phase 0
evolves the v0.1 gates: the zero-network grep becomes a confinement grep that
permits `std.http`/`std.net` under `src/providers/transport*` and nowhere else,
tests move inside a network-denied namespace so a stray socket fails rather than
flakes, and a fake API key is planted so that finding it in any output surface is
a red build. Phase 1 grows `tugproto` — additive variants on `StreamEvent`, the
taxonomy as data, request and model descriptors, and one ndjson encoder whose
bytes are simultaneously what `--json` prints in Phase 8 and what plugins speak in
v0.5. Phase 2 writes the SSE parser: a pure incremental push parser in a new
`tugproviders` module, shaped exactly like `src/shell/input/decoder.zig` — caller
owns the buffers, `feed` then `next`, partial input is not an error — because that
is the shape this codebase already proved on the other untrusted byte stream.

**Tech stack:** Zig 0.16.0 (`build.zig.zon` `minimum_zig_version`), no
dependencies. POSIX `sh`, `util-linux` `unshare(1)`, `valgrind`. GitHub Actions on
`ubuntu-24.04`.

## Global Constraints

Copied from `.artifacts/ROADMAP.md` § v0.2 and `.artifacts/v0.2.md` § Ground
rules, § Phases 0–2. Every task's requirements implicitly include this section.

- **Confinement, not prohibition.** `std.http`, `std.net`, `std.posix.socket` and
  `std.crypto.tls` may appear only under `src/providers/transport*`. Anywhere else
  fails the build. `DR-016` is where that evolution is written down; the v0.1
  Definition-of-Done line "the network gate was never legitimately silenced" stays
  true because the gate is narrowed in a commit that says so, never deleted.
- **`tugcore` stays freestanding.** No `std.fs`, no `std.posix`, no `std.Thread`,
  no clocks, and — new this version — no import of `tugproviders`. `zig build
  wasm-check` is the tripwire and it stays green in every task.
- **Every stream-consuming parser** gets three things in its first commit: a
  `@setRuntimeSafety(true)` scope, a `fuzz:` test target, and a
  chunking-invariance property test. Phase 2's parser is the first; the Phase 4
  mappers inherit the rule.
- **A gate that has never fired is a decoration.** Every gate added here is
  watched to fail on purpose before it is trusted, and each task says how.
- **Checked-in fixtures never contain credentials.** The canary grep over
  `testdata/` enforces it, starting in Task 6 rather than at v0.9.
- **Budgets may tighten; they never silently loosen.** A number that moves needs a
  line in `CHANGELOG.md` saying why. Task 3 moves one, and says why.
- **Line endings.** `.gitattributes` pins `*.sh`, `*.zig`, `*.toml` and `*.zon` to
  LF. A new shell script must be LF or `sh` rejects `set -eu\r` on the machine tug
  is developed on. New fixture files under `testdata/fixtures/` are byte-exact and
  **must** be pinned too — see Task 5.
- **Verification is on POSIX.** Development is Windows; every command in this plan
  runs under WSL:
  `wsl.exe -e bash -lc 'cd /mnt/c/Development/VCS/VCS/tug && <command>'`.
- **CI wall clock is five minutes** and the `wall-clock` job fails the run over it.
  New PR jobs run in parallel with the existing ones and **must** be added to that
  job's `needs:` list, or a failure in them cannot fail the run. Anything that
  cannot hold the wall goes to `nightly.yml` instead (Task 4).
- **Budgets, as of the start of this milestone.** Binary 196,520 B; `--version`
  0.521 ms against 2 ms; 411 tests; ceiling 500 KiB with a 211 KiB ratchet — both
  of which Task 3 replaces for the duration of v0.2.

## What this milestone cannot close, and why

1. **No fixture is a real recording yet.** `tug dev record` is Phase 9. Task 5
   creates the layout and the metadata convention, and Tasks 11–13 seed the corpus
   with hand-written `.sse` files whose sidecars say `capture = "handwritten"`.
   That is the honest state: the format is proven, the corpus is synthetic, and
   Phase 9 replaces the bodies without touching the layout.
2. **Valgrind's scope is a placeholder.** Task 4 stands the job up against a
   scripted mock session, because that is the only complete path through the
   binary that exists before providers land. Phase 10 points it at the SSE, mapper
   and transport tests. The job existing and failing on purpose now is what stops
   Phase 10 from discovering that the runner has no `valgrind` at all.
3. **The confinement grep guards a directory that does not exist yet.** By design.
   The rule is written before the code it constrains, exactly as v0.1 wrote the
   network gate before there was anything to catch.

- [ ] **Step 1: Write DR-016**

Create `docs/decisions/DR-016-network-confinement.md` following the shape of
`docs/decisions/DR-000-template.md`. It must state, in prose:

- **Context.** v0.1 shipped a grep that fails the build on `std.http`, `std.net`,
  `std.posix.socket` and `std.crypto.tls` anywhere under `src/`. v0.2 legitimately
  introduces all four. Deleting the gate would make v0.1's strongest claim retire
  quietly at exactly the moment it starts to matter.
- **Decision.** The gate narrows rather than dies. The four patterns are permitted
  under `src/providers/transport` and forbidden everywhere else, including the
  rest of `src/providers/`. `tugcore`'s `wasm32-freestanding` job is unchanged and
  remains the second, independent guard on the core.
- **Consequences.** Every socket in tug is reachable from one directory, so the
  Phase 3 `Transport` seam is enforced mechanically and not by review. A provider
  mapper that reaches for a socket fails CI with a message naming this DR. The
  cost: moving transport code requires editing this gate, which shows up in a
  diff — which is the mechanism.
- **Alternatives rejected.** Deleting the gate (loses the claim). An allowlist of
  individual files (churns on every new file). A build-system module boundary
  (Zig has no import restriction that would catch `@import("std").http`).

- [ ] **Step 2: Rewrite the gate**

Replace `scripts/no-network.sh` in full:

```sh
#!/bin/sh
# The network confinement tripwire (DR-016).
#
# v0.1 forbade network code outright. v0.2 needs it, so the gate narrows instead
# of dying: sockets and TLS live under src/providers/transport and nowhere else,
# which is what makes the Phase 3 Transport seam a mechanical fact rather than a
# review convention.
#
# usage: no-network.sh [directory]
set -eu

root=${1:-src}
pattern='std\.http|std\.net|std\.posix\.socket|std\.crypto\.tls'
allowed='^src/providers/transport'

hits=$(grep -rnE "$pattern" "$root" | grep -vE "$allowed" || true)

if [ -n "$hits" ]; then
    echo "$hits" >&2
    echo "" >&2
    echo "no-network: sockets and TLS belong under src/providers/transport (DR-016)." >&2
    echo "The matches above are outside it and fail the build." >&2
    exit 1
fi

echo "no-network: confined ($root)"
```

### Task 2: Tests run with no network at all

**Files:**
- Create: `scripts/offline.sh`
- Modify: `.github/workflows/ci.yml` (the `test` job's run step)

**Interfaces:**
- Consumes: nothing from earlier tasks.
- Produces: `scripts/offline.sh <command> [args…]` — runs the command inside a
  network namespace with no interfaces except a loopback it brings up
  best-effort. Exit status is the command's. Consumed by Task 4 (nightly), Task 13
  (the demo gate), Phase 7 (pty goldens), Phase 8 (the CI-container test) and
  Phase 9 (the replay proof).

- [ ] **Step 1: Write the wrapper**

```sh
#!/bin/sh
# Runs a command with no network at all.
#
# v0.2's claim is that CI never touches a network. A grep proves nothing about
# what a test does at runtime; a namespace with no interfaces does. A test that
# opens a socket here does not flake, it fails.
#
# Loopback is brought up because the Phase 10 bench server needs it, and a
# loopback-only namespace is still a namespace with no route off the machine.
#
# usage: offline.sh <command> [args...]
set -eu

if [ "$#" -eq 0 ]; then
    echo "offline: usage: offline.sh <command> [args...]" >&2
    exit 2
fi

if ! command -v unshare >/dev/null 2>&1; then
    echo "offline: unshare(1) not found; install util-linux." >&2
    exit 2
fi

# -r maps the caller to root inside the namespace, which is what makes -n work
# without sudo on a stock GitHub runner. If the kernel refuses unprivileged user
# namespaces, unshare fails loudly rather than running with a network.
exec unshare -rn sh -c 'ip link set lo up 2>/dev/null || true; exec "$@"' sh "$@"
```

### Task 4: CI splits, and valgrind gets a home

**Files:**

**Interfaces:**

- [ ] **Step 1: Write the valgrind scope script**

```sh
#!/bin/sh
# Memcheck over what v0.2 can currently run end to end.
#
# Scope is deliberately narrow and deliberately temporary: today it is one
# scripted mock session, because that is the only complete path through the
# binary that exists before providers land. Phase 10 points it at the SSE parser,
# the provider mappers and the transport tests. What matters now is that the job
# exists, the runner has valgrind, and a leak turns it red.
#
# usage: valgrind-scope.sh <binary>
set -eu

binary=${1:?usage: valgrind-scope.sh <binary>}

if ! command -v valgrind >/dev/null 2>&1; then
    echo "valgrind-scope: valgrind not found." >&2
    exit 2
fi

valgrind \
    --error-exitcode=99 \
    --errors-for-leak-kinds=definite \
    --leak-check=full \
    --track-origins=yes \
    "$binary" --provider mock --once --mock-cadence instant

echo "valgrind-scope: clean ($binary)"
```

- [ ] **Step 2: Run it, watch it pass**

```

```

Expect: `valgrind-scope: clean`. If WSL has no `valgrind`, install it

- [ ] **Step 4: Create the nightly workflow**

```yaml
name: nightly

# The PR pipeline holds a five-minute wall. Deep fuzzing and a full-session
# valgrind cannot, and pretending otherwise is how a five-minute wall becomes a
# fifteen-minute one. They run here instead: a failure pages the changelog, not
# the pull request.
on:
  schedule:
    - cron: "17 3 * * *"
  workflow_dispatch:

permissions:
  contents: read

env:
  ZIG_VERSION: 0.16.0

jobs:
  valgrind-full:
    name: valgrind over a full session
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
      - uses: mlugg/setup-zig@v2
        with:
          version: ${{ env.ZIG_VERSION }}
      - run: sudo apt-get update && sudo apt-get install -y valgrind
      - run: zig build -Doptimize=ReleaseSafe
      - run: sh scripts/offline.sh sh scripts/valgrind-scope.sh zig-out/bin/tug

  fuzz-deep:
    name: deep fuzz
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
      - uses: mlugg/setup-zig@v2
        with:
          version: ${{ env.ZIG_VERSION }}
      # `zig build fuzz -- --fuzz` starts a server and does not terminate, so the
      # nightly gives it a wall-clock box and treats a timeout as success. A
      # crash inside the box is a real failure and exits nonzero.
      - run: |
          set -eu
          status=0
          timeout --preserve-status 900 \
            sh scripts/offline.sh zig build fuzz -- --fuzz || status=$?
          if [ "$status" -eq 143 ] || [ "$status" -eq 0 ]; then
            echo "fuzz-deep: no crashes in 15 minutes"
          else
            echo "fuzz-deep: fuzzer exited $status" >&2
            exit "$status"
          fi
```

```zig
//! What tug asks a model for.
//!
//! One shape, two very different APIs downstream: the Anthropic Messages API and
//! the OpenAI chat-completions shape both fall out of this through a pure
//! builder in Phase 4. Anything one API supports and the other does not stays out
//! of this type and lives in the builder, or it becomes a lie in the shared
//! vocabulary.
//!
//! `Content` is a tagged union with exactly one variant today. That is
//! deliberate: v0.7 adds images, and a union that already exists grows a variant
//! without changing the shape of every function that takes one.

const std = @import("std");

pub const Role = enum { user, assistant };

pub const Content = union(enum) {
    text: []const u8,
};

/// Borrowed throughout. A request is built inside a per-request arena from a
/// conversation that outlives it.
pub const Message = struct {
    role: Role,
    content: []const Content,
};

pub const Request = struct {
    model: []const u8,
    messages: []const Message,
    system: ?[]const u8 = null,
    /// Both APIs require a cap; Anthropic rejects a request without one. 4096 is
    /// large enough for a normal answer and small enough that a runaway costs
    /// cents. Config overrides it (Phase 6).
    max_tokens: u32 = 4096,
    /// Absent means "the provider's default", which is not the same as 1.0 and
    /// is why this is optional rather than defaulted.
    temperature: ?f32 = null,
};
```

```zig
//! What a model is, and what it costs.
//!
//! Prices are data, not knowledge: they drift, they differ per account, and a
//! harness that hardcodes them silently reports the wrong number forever. The
//! table ships with defaults and the config overrides any entry (Phase 6). An
//! unknown model has a zero price and renders tokens without a cost, which is
//! honest; a guess would not be.

const std = @import("std");

const stream = @import("stream.zig");

pub const ProviderId = enum { anthropic, openai_compat, mock };

/// US dollars per million tokens. Four numbers because prompt caching is priced
/// on three of them, and a single input price would make the cache invisible in
/// exactly the version that turns caching on.
pub const Price = struct {
    input_per_mtok: f64 = 0,
    output_per_mtok: f64 = 0,
    cache_read_per_mtok: f64 = 0,
    cache_write_per_mtok: f64 = 0,
};

pub const Model = struct {
    id: []const u8,
    provider: ProviderId,
    context_window: u32,
    price: Price = .{},

    /// Dollars for one request's usage. f64 throughout: these are cents-to-
    /// dollars numbers being displayed, never accumulated into a ledger, and the
    /// alternative — fixed-point micro-dollars — buys precision nothing in v0.2
    /// spends.
    pub fn cost(self: Model, usage: stream.Usage) f64 {
        const per_mtok = 1_000_000.0;
        const input: f64 = @floatFromInt(usage.input_tokens);
        const output: f64 = @floatFromInt(usage.output_tokens);
        const cache_read: f64 = @floatFromInt(usage.cache_read_tokens);
        const cache_write: f64 = @floatFromInt(usage.cache_creation_tokens);

        return (input * self.price.input_per_mtok +
            output * self.price.output_per_mtok +
            cache_read * self.price.cache_read_per_mtok +
            cache_write * self.price.cache_write_per_mtok) / per_mtok;
    }
};
```

- [ ] **Step 3: Write the encoder**

```zig
//! The ndjson encoding of a stream event.
//!
//! One line per event, `\n`-terminated, no pretty printing, keys in a fixed
//! order. These exact bytes are what `tug -p --json` prints (Phase 8) and what a
//! plugin sends over stdio (v0.5), which is why the encoding lives here in the
//! wire vocabulary rather than in either consumer. Two producers of the same
//! bytes is how they drift.
//!
//! The shape is flat and tagged — `{"type":"text_delta","text":"hi"}` — rather
//! than Zig's natural `{"text_delta":"hi"}`, because every consumer that is not
//! Zig switches on a field, and a discriminant that changes the whole object's
//! shape is hostile to `jq`.
//!
//! Field order is part of the format: the goldens compare bytes.

const std = @import("std");

const stream = @import("stream.zig");

pub const StreamEvent = stream.StreamEvent;

/// The flat form. Every field optional so one struct covers every variant, which
/// is what lets `std.json` parse a line before anyone knows which variant it is.
pub const Wire = struct {
    type: []const u8,
    text: ?[]const u8 = null,
    id: ?[]const u8 = null,
    name: ?[]const u8 = null,
    arguments: ?[]const u8 = null,
    input_tokens: ?u32 = null,
    output_tokens: ?u32 = null,
    cache_read_tokens: ?u32 = null,
    cache_creation_tokens: ?u32 = null,
    reason: ?[]const u8 = null,
    kind: ?[]const u8 = null,
    message: ?[]const u8 = null,
    retry_after_ms: ?u32 = null,
};

pub fn writeEvent(event: StreamEvent, out: *std.Io.Writer) std.Io.Writer.Error!void {
    switch (event) {
        .text_delta => |text| {
            try out.writeAll("{\"type\":\"text_delta\",\"text\":");
            try std.json.Stringify.encodeJsonString(text, .{}, out);
            try out.writeAll("}\n");
        },
        .tool_call_delta => |call| {
            try out.writeAll("{\"type\":\"tool_call_delta\",\"id\":");
            try std.json.Stringify.encodeJsonString(call.id, .{}, out);
            try out.writeAll(",\"name\":");
            try std.json.Stringify.encodeJsonString(call.name, .{}, out);
            try out.writeAll(",\"arguments\":");
            try std.json.Stringify.encodeJsonString(call.arguments, .{}, out);
            try out.writeAll("}\n");
        },
        .usage => |usage| try out.print(
            "{{\"type\":\"usage\",\"input_tokens\":{d},\"output_tokens\":{d}," ++
                "\"cache_read_tokens\":{d},\"cache_creation_tokens\":{d}}}\n",
            .{
                usage.input_tokens,
                usage.output_tokens,
                usage.cache_read_tokens,
                usage.cache_creation_tokens,
            },
        ),
        .stop => |stop| try out.print(
            "{{\"type\":\"stop\",\"reason\":\"{s}\"}}\n",
            .{@tagName(stop.reason)},
        ),
        .err => |err| {
            try out.print("{{\"type\":\"error\",\"kind\":\"{s}\",\"message\":", .{@tagName(err.kind)});
            try std.json.Stringify.encodeJsonString(err.message, .{}, out);
            if (err.retry_after_ms) |ms| try out.print(",\"retry_after_ms\":{d}", .{ms});
            try out.writeAll("}\n");
        },
    }
}

pub const DecodeError = error{
    UnknownEventType,
    UnknownStopReason,
    UnknownErrorKind,
    MissingField,
};

pub fn parseEvent(gpa: std.mem.Allocator, line: []const u8) !std.json.Parsed(Wire) {
    return std.json.parseFromSlice(Wire, gpa, line, .{ .ignore_unknown_fields = true });
}

pub fn fromWire(wire: Wire) DecodeError!StreamEvent {
    if (std.mem.eql(u8, wire.type, "text_delta")) {
        return .{ .text_delta = wire.text orelse return error.MissingField };
    }
    if (std.mem.eql(u8, wire.type, "tool_call_delta")) {
        return .{ .tool_call_delta = .{
            .id = wire.id orelse return error.MissingField,
            .name = wire.name orelse "",
            .arguments = wire.arguments orelse "",
        } };
    }
    if (std.mem.eql(u8, wire.type, "usage")) {
        return .{ .usage = .{
            .input_tokens = wire.input_tokens orelse 0,
            .output_tokens = wire.output_tokens orelse 0,
            .cache_read_tokens = wire.cache_read_tokens orelse 0,
            .cache_creation_tokens = wire.cache_creation_tokens orelse 0,
        } };
    }
    if (std.mem.eql(u8, wire.type, "stop")) {
        const name = wire.reason orelse return error.MissingField;
        const reason = std.meta.stringToEnum(stream.StopReason, name) orelse
            return error.UnknownStopReason;
        return .{ .stop = .{ .reason = reason } };
    }
    if (std.mem.eql(u8, wire.type, "error")) {
        const name = wire.kind orelse return error.MissingField;
        const kind = std.meta.stringToEnum(stream.ErrKind, name) orelse
            return error.UnknownErrorKind;
        return .{ .err = .{
            .kind = kind,
            .message = wire.message orelse "",
            .retry_after_ms = wire.retry_after_ms,
        } };
    }
    return error.UnknownEventType;
}
```

Note `"error"` on the wire against `err` in Zig: `err` is the v0.1 field name and

- [ ] **Step 3: Write the parser**

`src/providers/sse.zig`. The design, stated before the code because it is the part
that has to survive Phase 4:

- **Caller owns both buffers.** `scratch` holds bytes that have arrived and not
  yet been consumed into a line; `data` accumulates the joined `data:` field
  across the lines of one event. Neither grows. This is the `Decoder` contract
  from `src/shell/input/decoder.zig`, and a second memory model for the second
  byte stream would be a second thing to get wrong.
- **`feed` copies and can fail; `next` cannot.** Overflow is the only failure
  framing has, and it happens when bytes arrive, not when events leave.
- **A returned `ServerEvent` borrows from `data` and `scratch`** and is valid
  until the next `feed` or `next`. The consumer maps it immediately; nothing holds
  one. The test helper above duplicates for exactly this reason.
- **`@setRuntimeSafety(true)` at the top of the struct's scope**, per the
  input-facing parser rule. This is bytes from a network in a `ReleaseSmall`
  binary; a bounds error must trap, not be undefined.

Line splitting handles all three terminators — `\n`, `\r\n`, and a bare `\r`. A
trailing `\r` at the end of a fed buffer is held back rather than treated as a
terminator, because the `\n` that would pair with it may be in the next chunk;
that single case is what most of Task 12's property test is about.

Field parsing per the spec: split on the first `:`; strip a single leading space
from the value; a line with no `:` is a field name with an empty value; a line
starting with `:` is a comment and is ignored entirely; `retry:` parses as a
decimal integer and is ignored when it does not parse; unknown field names are
ignored.

Keep the whole thing in one struct inside the safety scope, and keep the count
honest — the roadmap promised ~150 lines and Task 13 Step 8 checks.

```zig
fn parseOne(_: void, smith: *std.testing.Smith) anyerror!void {
    var input: [512]u8 = undefined;
    const len = smith.slice(&input);

    var scratch: [1024]u8 = undefined;
    var data: [1024]u8 = undefined;
    var parser: Parser = .init(&scratch, &data);

    // Overflow is a legitimate outcome of arbitrary bytes, not a crash.
    parser.feed(input[0..len]) catch return;

    var emitted: usize = 0;
    while (parser.next()) |_| {
        emitted += 1;

        // emit more events than it was given bytes. A violation means the
        // dispatch loop is not consuming — which is the hang this bound catches.
        try testing.expect(emitted <= len);

}
```

```zig
//! Debug-build-only subcommands.
//!
//! `tug dev sse-dump` is the M1 demo and a permanent debugging tool: when a
//! provider misbehaves, the first question is always whether the bytes framed the
//! way the parser thinks they did, and this answers it without a debugger.
//!
//! Not compiled into a release build. These read stdin and write stdout with no
//! terminal setup at all, which also makes them the first thing in tug shaped
//! like Phase 8's pipe frontend.

const std = @import("std");

const sse = @import("tugproviders").sse;

/// One line per event: the event name, the byte length of the data, then the
/// data with newlines escaped so one event is always one line. Length before
/// content because the first question about a delta is usually how big it is.
fn writeEvent(event: sse.ServerEvent, out: *std.Io.Writer) std.Io.Writer.Error!void {
    try out.print("event={s} len={d} data=", .{
        if (event.event.len == 0) "message" else event.event,
        event.data.len,
    });
    for (event.data) |byte| switch (byte) {
        '\n' => try out.writeAll("\\n"),
        '\r' => try out.writeAll("\\r"),
        else => try out.writeByte(byte),
    };
    try out.writeByte('\n');
}
```

Plus the driver: a read loop over stdin into a 4 KiB chunk buffer, `feed`, drain
`next`, flush at EOF. On `error.LineTooLong` or `error.DataTooLong`, print
`decode error: <name>` to stderr and return exit code 7.

In `src/main.zig`: add `dev_sse_dump` to `Command`, parse `dev sse-dump` as a
two-word subcommand (it is the only one, so a literal comparison is enough — a
subcommand table for one subcommand is the abstraction this codebase does not
build), and gate it on `builtin.mode == .Debug`, printing
`tug: dev subcommands are debug builds only` otherwise. Add three lines to `usage`
under a new `development:` heading.

## Handoff

This plan is a hypothesis about work not yet done. Three places are the likeliest
to be wrong, and the executor's job includes saying so rather than forcing them:

1. **`unshare -rn` on the CI image.** If the pinned runner refuses unprivileged
   user namespaces, Task 2 falls back to `sudo unshare -n`, and the fallback goes
   in the script with a comment — not in a shell one-liner in the workflow.
2. **The two-buffer parser.** If `scratch` and `data` turn out to want to be one
   buffer, that is a better design; Task 10's interface block is what changes, and
   it changes before Task 11 depends on the old shape.
3. **The ndjson field order.** Task 9 freezes bytes that v0.5's plugin protocol
   will speak. If an ordering reads badly in `jq` output, now is the moment to
   change it; after Phase 8 ships `--json` it is a wire-format change.

Next milestone is **M2 «First light»** — Phases 3 and 4, the transport seam and
the two providers. It gets its own plan, written after this one is green.
