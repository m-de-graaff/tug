# tug v0.2 «Halyard» — M3 «Unbreakable-ish» (Phases 5–7) — Implementation Plan

> **To execute:** use the `executing-plans` skill. Steps use `- [ ]` for tracking.

**Goal:** pull the network cable mid-stream and get a clean taxonomy error, the
partial block committed, and the usage so far. `Esc` cancels instantly. `/model`
switches mid-conversation and the cost line renders. All of it in the shell, and
all of it proven offline from recorded bytes.

**Architecture:** three layers, and only the third touches the terminal. Phase 5
turns transport failures and HTTP status codes into the five-variant taxonomy a
user can act on, and puts a retry engine in front of the stream whose hardest
rule is about when *not* to retry. Phase 6 grows the conversation and the price
table inside `tugcore`, where they stay freestanding because v0.4's sessions will
need them there. Phase 7 replaces the v0.1 shell's mock-shaped `startTurn` with a
provider *source* — mock, fixture or HTTP behind one seam — so that the entire
turn lifecycle becomes pty-goldenable with no socket in it.

**Tech stack:** Zig 0.16.0, no dependencies. POSIX `sh`, `unshare(1)`. GitHub
Actions on `ubuntu-24.04`.

## Global Constraints

Copied from `.artifacts/ROADMAP.md` § v0.2 and `.artifacts/v0.2.md` § Ground
rules, § Phases 5–7. Every task's requirements implicitly include this section.

- **Confinement (`DR-016`).** Sockets and TLS only under
  `src/providers/transport`. `sh scripts/no-network.sh` runs in every task's
  verification, and it matches text — a comment naming `std.http` outside that
  directory trips it, which is deliberate.
- **`tugcore` stays freestanding.** Phase 6 puts the conversation and the model
  table there, so `zig build wasm-check` is not a formality this milestone: it is
  the gate on the two files being written. No `std.fs`, no `std.posix`, no
  `std.Thread`, no clock, no `tugproviders` import.
- **Every stream-consuming parser** gets `@setRuntimeSafety(true)`, a `fuzz:`
  target and a chunking-invariance property in its first commit. Phase 5 adds one
  parser — the `Retry-After` header — and it is untrusted input like any other.
- **A gate that has never fired is a decoration.** Every gate added here is
  watched to fail on purpose, and each task says how.
- **The canary rule.** `providers.canary.key` goes through every new auth path —
  `key_cmd`'s stdout and stderr especially — and every new output surface is
  asserted not to contain it. `sh scripts/canary-grep.sh` in every verification.
- **The stream idempotency line**, stated once here and enforced in Task 3: a
  request that has yielded zero content events may be retried; after the first
  `text_delta`, never. Partial output is the user's, not the retrier's.
- **Budgets may tighten; they never silently loosen.** A number that moves needs
  a `CHANGELOG.md` line saying why.
- **Line endings.** `*.sh`, `*.zig`, `*.toml`, `*.zon` are LF;
  `testdata/fixtures/**` is `-text` and byte-exact. `.github/workflows/*.yml` is
  **CRLF** in this checkout — read and write it with universal newlines or the
  anchors will not match.
- **Never stage from WSL.** `git add` and `git commit` from PowerShell.
- **Verification is on POSIX**, under WSL, with the Zig cache off `drvfs`:

  ```
  wsl.exe -e bash -lc 'cd /mnt/c/Development/VCS/VCS/tug && \
    export ZIG_LOCAL_CACHE_DIR=$HOME/.cache/tug-zig && <command>'
  ```

- **Never trust a green from a build whose output you filtered.** M2 lost an hour
  to a stale binary because `zig build test 2>&1 | grep -E "error"` hid a compile
  error and `ls -t` then found yesterday's artifact. Grep for `Build Summary` as
  well as for errors, or read the exit code.
- **CI wall clock is five minutes.** New PR jobs must be added to the

### Task 3: The retry engine

**Files:**
- Create: `src/providers/retry.zig`
- Create: `docs/decisions/DR-019-retry-policy.md`
- Modify: `src/providers/root.zig`

**Interfaces:**
- Consumes: `proto.ErrKind`, `proto.StreamEvent`, `core.Provider`.
- Produces: `retry.Policy` (`max_attempts`, `max_elapsed_ms`, `base_ms`,
  `cap_ms`); `retry.classOf(kind, has_retry_after) retry.Class`;
  `retry.delayMs(policy, attempt, retry_after_ms, random) u32`;
  `retry.Retrying` — a `core.Provider` wrapping a stream factory. Task 11 wires
  the notice; Task 10 constructs it.

- [ ] **Step 1: Write DR-019**

The argument, in the repository's voice:

> **Decision.** Retry `transport`, `server`, and `rate_limit`-with-a-header.
> Never `auth` — a wrong key is wrong on the fourth attempt too, and retrying it
> is how an account gets locked. Never `decode` — bytes that did not mean what
> they claimed will not mean it later, and a retry loop over a parser bug is a
> parser bug that costs money.
>
> **`rate_limit` without a header is not retried.** A 429 with no `Retry-After`
> is a provider declining to say when, and guessing is how a client becomes part
> of the incident. The user is told to wait, which is the same information
> without the traffic.
>
> **The idempotency line.** A request that has yielded zero content events may be
> retried; after the first `text_delta`, never. Partial output is the user's.
> Retrying after it means either discarding what they already read, or splicing
> two model responses together and calling it one — and the second is worse,
> because nobody can see it happened.
>
> **Jittered exponential backoff**, full jitter: `random(0, min(cap, base * 2^n))`.
> Not equal jitter and not none: the failure this exists to avoid is every tug on
> a team retrying in lockstep after one provider blip, and full jitter is the
> variant that flattens that best.
>
> **Two budgets, and the elapsed one is the real one.** Max attempts stops a
> pathological loop; max elapsed is what a human notices. A harness that spends
> ninety seconds retrying silently has hung, whatever its attempt counter says.

- [ ] **Step 4: Implement**

`Retrying` is a `core.Provider` over a **factory**: a function that opens a fresh
`Stream` for one attempt. It cannot re-use a `Stream`, because a used transport
has a consumed response in it.

```zig
pub const Factory = struct {
    context: ?*anyopaque = null,
    /// Opens attempt `n`. Returns null when the factory itself cannot try again
    /// — a transport that could not be constructed is not a retry case.
    open: *const fn (context: ?*anyopaque, attempt: u32) ?core.Provider,
};

pub const Retrying = struct {
    factory: Factory,
    policy: Policy,
    random: std.Random,
    /// Injected: the engine sleeps and reads a clock, and neither belongs to it.
    /// A test passes a fake that advances a counter, which is what makes the
    /// elapsed-budget test instant rather than four seconds long.
    clock: Clock,
    /// The idempotency line, as one bool.
    yielded_text: bool = false,
    ...
};
```

`Clock` is two function pointers, `nowMs` and `sleepMs`, and `sleepMs` returns
`bool` — false when the wait was interrupted, which is how `Esc` aborts a retry
wait without the engine knowing what `Esc` is.

  `{ key: []const u8, origin: Origin, problem: ?[]const u8 }`. Task 10 calls it.

- [ ] **Step 1: Write DR-024**

> **Decision.** Four sources, in order: `--key` → the preset's environment
> variable → config `key = "…"` → config `key_cmd = "pass show anthropic"`.
> First hit wins; `key_cmd` is spawned once at first use and cached in memory for
> the process.
>
> **Why `key_cmd` at all.** A key in a config file is a key in a backup, in a
> dotfiles repository, and in every screen-share of that file. `key_cmd` is the
> one mechanism that lets a secret stay in whatever the user already trusts —
> `pass`, `age`, a keychain CLI, a vault agent — without tug depending on any of
> them. The dependency inverts: tug learns nothing about secret storage, and
> every secret store already knows how to print to stdout.
>
> **Rejected: a keychain integration.** Three platforms, three APIs, two of them
> needing a C dependency in a build that has none, to do what one line of config
> already does through a CLI the user has installed.
>
> **Rejected: a credentials file with permission checks.** Checking that a file
> is `0600` is security theatre on Windows, it is bypassed by every backup tool,
> and it invites the belief that the file is safe.
>
> **`key_cmd` failure surfaces the command's stderr**, verbatim and scrubbed.
> The failure is almost always the user's — a locked keychain, a typo'd entry —
> and the command's own words are the ones that help. Scrubbed because a secret
> store's error message is exactly the place a key gets printed by accident.
>
> **Cached for the process lifetime**, not per request. Spawning `pass` per turn
> means a GPG prompt per turn, and a harness that asks for a passphrase mid-answer
> has broken the thing it was for.

## Handoff

This plan is a hypothesis. Four places are the likeliest to be wrong:

1. **The clock injection in Task 2.** Passing `now_epoch_s` into a pure seam is
   the cheapest way to keep the date parser testable, and it may turn out that
   only the retry engine needs it — in which case `Retry-After` stays a raw
   string all the way up and the parse happens there. Decide before Task 3
   depends on the shape.
2. **The config schema's `[models.<id>]` tables (Task 7).** The v0.1 TOML scanner
   was written for scalars and one array. If it cannot express a table per model,
   the honest answer is a flat `models.<id>.input` key, not a TOML rewrite.
3. **`repl.Session`'s field count (Task 10).** It already carries the mock, the
   cadence, the runner and a stop flag as fields because the provider thread
   borrows them. Adding a conversation, a retry engine and a source may be the
   moment that struct wants splitting into `Session` and `Turn`. That is a
   better design and it is also a much larger diff; decide deliberately.
4. **Task 11 is the largest task here.** If it wants splitting, split it at the
   cancel/notice line: cancellation and the exit ladder are one change, the
   notice rendering is another, and they share no state.

Next milestone is **M4 «Scriptable & honest»** — Phases 8, 9 and 10: print mode,
the recorder, the benches and the tag.
