# tug v0.1 «Hull» — Milestone 1 «Raw echo» Implementation Plan

> **To execute:** use the `executing-plans` skill. Steps use `- [ ]` for tracking.

**Goal:** Ship Phases 0–2 of `.artifacts/v0.0.md` — a repo where every budget gate
already runs, a terminal substrate that can never leave the terminal broken, and an
input decoder that turns bytes into `KeyEvent`/`PasteEvent` without panicking.

**Architecture:** Four Zig modules with hard boundaries, established before the code
that fills them. `tugproto` is the wire vocabulary and depends on nothing. `tugcore`
is sans-IO and must compile for `wasm32-freestanding` — no `std.fs`, no `std.posix`,
no threads, no clocks. `tugshell` owns the terminal: capability detection, mode
stack, and a pure-state-machine input decoder. `tug` is a thin executable that wires
them together.

**Tech stack:** Zig 0.16.0 (pinned via `minimum_zig_version` in `build.zig.zon`). No
third-party dependencies in this milestone. GitHub Actions on `ubuntu-latest` for the
gates, plus a `windows-latest` compile-only job.

## Global Constraints

Copied from `.artifacts/v0.0.md` § Ground rules and § Budgets. Every task's
requirements implicitly include this section.

- Every test allocates through `std.testing.allocator`. A leaked byte is a failed test.
- `zig fmt --check` passes.
- Zero network code, mechanically enforced: CI greps `src/` for `std.http` and
  `std.net` and fails the build on a hit.
- Binary ≤ 500 KiB (`ReleaseSmall`, stripped, Linux x86_64).
- `tug --version` ≤ 2 ms.
- Cold start → interactive prompt ≤ 10 ms. The gate lands in Phase 11; the fast paths
  that make it reachable are built from Phase 0.
- Idle RSS ≤ 10 MiB.
- CI wall clock ≤ 5 min.
- `tugcore` stays freestanding. The `wasm32-freestanding` CI job is the tripwire.
- Every non-obvious choice gets `docs/decisions/DR-NNN-*.md`.

### Platform note — a deliberate deviation from the spec

`.artifacts/v0.0.md` Phases 1–2 assume POSIX: `termios`, `ioctl`, `SIGWINCH`. The
roadmap marks Windows tier-2, "must compile; nothing more". Development happens on
Windows, so a binary that merely compiles there cannot be dogfooded at all, and the
dogfood gate arrives in v0.3.

This plan implements the terminal backend behind one interface with two backings:
POSIX (`termios`, complete, tier-1) and Windows (`SetConsoleMode` plus VT input,
tier-2). The Windows backing is not certified, is excluded from the terminal matrix,
and its limits are recorded in `DR-009`. This costs one file and one switch; no
tier-1 behaviour changes.

### Task 7: Input decoder, legacy sequences

**Files:**
- Create: `src/shell/input/key.zig`, `src/shell/input/decoder.zig`
- Test: table-driven inline tests in `decoder.zig`

**Interfaces produced:**

```zig
// src/shell/input/key.zig
pub const Mods = packed struct(u4) {
    shift: bool = false, alt: bool = false, ctrl: bool = false, super: bool = false,
};
pub const Key = union(enum) {
    char: u21,
    enter, tab, backspace, escape, delete, insert,
    up, down, left, right, home, end, page_up, page_down,
    f: u5,
};
pub const KeyEvent = struct { key: Key, mods: Mods = .{} };
pub const PasteEvent = struct { bytes: []const u8 };
pub const InputEvent = union(enum) { key: KeyEvent, paste: PasteEvent };

// src/shell/input/decoder.zig
pub const Decoder = struct {
    pub fn init(scratch: []u8) Decoder;
    /// Feeds bytes. Never allocates, never blocks, never fails.
    pub fn feed(self: *Decoder, bytes: []const u8) void;
    /// Drains one decoded event, or null when the buffer holds only a partial sequence.
    pub fn next(self: *Decoder) ?InputEvent;
    pub const unknown_sequence_cap: usize = 64;
};
```

- [ ] **Step 1: Write the failing tests** as one table, one row per sequence:

```zig
const cases = .{
    .{ "a",         Key{ .char = 'a' },  Mods{} },
    .{ "\x03",      Key{ .char = 'c' },  Mods{ .ctrl = true } },
    .{ "\r",        Key.enter,           Mods{} },
    .{ "\x7f",      Key.backspace,       Mods{} },
    .{ "\x1b[A",    Key.up,              Mods{} },
    .{ "\x1bOA",    Key.up,              Mods{} },
    .{ "\x1b[1;5A", Key.up,              Mods{ .ctrl = true } },
    .{ "\x1b[3~",   Key.delete,          Mods{} },
    .{ "\x1bb",     Key{ .char = 'b' },  Mods{ .alt = true } },
    .{ "\xc3\xa9",  Key{ .char = 0xe9 }, Mods{} },
};
```

- [ ] **Step 2: Run them, confirm they fail.**
- [ ] **Step 3: Implement the state machine** with states `ground`, `esc`, `csi`,
      `ss3`, `utf8`, `paste` and `unknown`. An unknown sequence is swallowed to its
      terminator with `unknown_sequence_cap` as the ceiling, counted, and dropped —
      never rendered, never fatal.
- [ ] **Step 4: Run them, confirm they pass.**
- [ ] **Step 5: Split-read test.** Feed every case one byte per `feed` call and assert
      the same events come out. This is the partial-UTF-8 and partial-CSI guarantee.
- [ ] **Step 6: Commit.**

### Task 8: Input decoder, kitty CSI-u, paste sanitization, fuzzing

**Files:**
- Modify: `src/shell/input/decoder.zig`
- Modify: `docs/decisions/DR-003-kitty-keyboard.md` (add the ESC timing)

**Interfaces:**
- Consumes: `Decoder` and `InputEvent` from Task 7.
- Produces: `pub fn setKittyActive(self: *Decoder, active: bool) void`.

- [ ] **Step 1: Write the failing tests**

```zig
test "kitty csi-u decodes shift+enter" {
    // ESC [ 13 ; 2 u  ->  KeyEvent{ .key = .enter, .mods = .{ .shift = true } }
}
test "paste content is sanitized" {
    // ESC [200~ a ESC [31m \x07 b \n ESC [201~  ->  PasteEvent{ .bytes = "ab\n" }
}
test "lone escape emits Escape when kitty is inactive" { ... }
test "unknown sequence past the cap is dropped, decoding resumes" { ... }
```

- [ ] **Step 2: Run them, confirm they fail.**
- [ ] **Step 3: Implement.** CSI-u parsing while kitty is active. Between `200~` and
      `201~`, strip `ESC` and every C0 byte except `\n` and `\t`: paste is untrusted
      input and an unsanitized paste is a terminal-injection vector. A lone `ESC` waits
      one short poll of roughly 30 ms for a continuation only while kitty is inactive;
      with the protocol active there is no ambiguity to resolve.
- [ ] **Step 4: Run them, confirm they pass.**
- [ ] **Step 5: Fuzz.** A `std.testing.fuzz` target asserting the decoder never panics,
      always consumes its input, and never emits more bytes than it was given. Runs
      locally now; a short smoke iteration goes into CI.
- [ ] **Step 6: `@setRuntimeSafety(true)`** on the decoder scope. This is the first
      parser in the shipped `ReleaseSmall` binary that touches untrusted input.
- [ ] **Step 7: Commit.**
