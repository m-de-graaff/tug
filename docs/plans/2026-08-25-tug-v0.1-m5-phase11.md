# tug v0.1 «Hull» — Phase 11: Hardening, budgets, matrix, ship — Implementation Plan

> **To execute:** use the `executing-plans` skill. Steps use `- [ ]` for tracking.

**Goal:** every budget the roadmap states becomes a number a CI job prints and
fails on, every claim the v0.1 Definition of Done makes is either green in CI or
recorded as unrecorded with the command that would close it, and the shell has
the documentation a stranger needs to build and use it.

**Architecture:** nothing new is designed here. Four budgets that have never had
a gate — cold start, idle RSS, idle CPU, and leak-freedom over a long session —
get one each, and each gate is a `scripts/*.sh` in the shape of the five that
already exist plus one CI job that runs it. Two of the four need the binary to
tell the truth about itself, so `--debug-first-paint` reports the microseconds
from process entry to the first flushed frame, and a Debug build swaps
`std.heap.smp_allocator` for `std.heap.DebugAllocator` so a leak is a nonzero
exit. The rest is documentation and a size gate that stops being only a ceiling
and becomes a ratchet as well.

**Tech stack:** Zig 0.16.0 (`build.zig.zon` `minimum_zig_version`), no
dependencies. POSIX `sh`, `script(1)` and `tmux` for the pty gates. GitHub
Actions on `ubuntu-24.04`.

---

## Global Constraints

Copied from `.artifacts/v0.0.md` § Ground rules, § Phase 11 and § v0.1
Definition of Done, and from the carried-forward items this phase is named in
(1, 3, 5, 6, 9, 14, 15, 18, 41). Every task's requirements implicitly include
this section.

- **Budgets may tighten; they never silently loosen.** A number that moves needs
  a line in `CHANGELOG.md` saying why. `scripts/size-gate.sh` takes its budget
  from the caller and has no opinion of its own; every new gate script does the
  same.
- **A gate that has never fired is a decoration.** Phase 0's own standard, and
  this phase is where it is finally paid in full: every gate added here is
  watched to fail on purpose before it is trusted, and each task says how.
- **`tugcore` stays freestanding.** No `std.fs`, no `std.posix`, no
  `std.Thread`, no clocks. Everything added in this phase lives in `tugshell`,
  `src/main.zig`, `scripts/`, `docs/` or `.github/`. `zig build wasm-check` is
  the tripwire.
- **Zero network code.** `scripts/no-network.sh` greps `src/` for `std.http` and
  `std.net`. Nothing in this phase legitimately silences it.
- **No configuration mistake is worth refusing to start.** A debug flag with a
  bad value degrades to its default; it is not a trust boundary.
- **Line endings.** `.gitattributes` pins `*.sh`, `*.zig`, `*.toml` and `*.zon`
  to LF. A new shell script must be LF or `sh` rejects `set -eu\r` on the
  machine tug is developed on. `*.md` is deliberately not pinned — see carried
  item 35 before "fixing" it.
- **Verification is on POSIX.** Development is Windows; `zig build test`,
  `zig fmt --check` and every `scripts/*.sh` run under WSL:
  `wsl.exe -e bash -lc 'cd /mnt/c/Development/VCS/VCS/tug && zig build test'`.
- **CI wall clock is five minutes** and the `wall-clock` job fails the run over
  it. New jobs run in parallel with the existing ones and **must** be added to
  that job's `needs:` list, or a failure in them cannot fail the run.
- **Budgets, as of the start of this phase.** Binary 196,520 B against 500 KiB
  (`ReleaseSmall`, stripped, `x86_64-linux-musl`). `--version` 0.521 ms against
  2 ms. 411 tests. Cold start, idle RSS, idle CPU and the 1,000-interaction leak
  gate have no CI number at all; producing those four is most of this phase.

## What this phase cannot close, and why

Stated here rather than discovered in Task 6. Two Definition-of-Done items need
something this environment does not have, and the plan's job is to make the gap
explicit and cheap to close rather than to pretend.

1. **kitty, alacritty, wezterm and ghostty have never seen tug.** Carried items
   3, 9, 14 and 15 are the same item, four phases running. tug is developed on
   Windows against a WSL toolchain and none of the four is installed there; CI

2. **Tagging `v0.1.0` publishes something.** Task 9 prepares the release and
   stops. It does not tag, does not push a tag and does not create a GitHub

### Task 1: The cold-start number

The 10 ms budget from the roadmap has never been measured, because until Phase 6
there was no prompt to measure to. Carried item 18 assigns it here.

**Files:**
- Modify: `src/shell/repl.zig` — the `Setup` struct, and `run` immediately after
  the first `screen.flush()`
- Modify: `src/main.zig` — `Command`, `parseArgs`, the `switch` in `main`,
  `printUsage`, and the test block
- Create: `scripts/first-paint.sh`
- Modify: `.github/workflows/ci.yml`

**Interfaces:**
- Produces:
  - `repl.Setup.first_paint: ?*std.Io.Clock.Timestamp = null` — when non-null,
    `run` stamps it immediately after the first frame is flushed and returns
    without entering the loop. Every `defer` still runs, so the terminal is
    restored and the mode stack popped exactly as on any other exit.
  - `--debug-first-paint`, a hidden debug flag in the shape of `--caps` and
    `--debug-keys`. Opens the terminal, paints one frame, prints
    `first paint: <n> us` to stdout, exits 0.
- Consumes: `std.Io.Clock.Timestamp.now(io, .awake)` and
  `Timestamp.durationTo(other).raw.nanoseconds` — the monotonic clock
  `src/shell/loop/wait.zig:53` already uses.

**Deviation from the phase checklist, decided here.** The checklist asks for an
invisible marker sequence that a harness timestamps, gated by a
`hyperfine`-wrapped pty run. That is two moving parts more than the number
needs, and it measures the wrong thing: `hyperfine` would have to time
`script -qec "tug …" /dev/null`, so `script`'s own fork and exec — a millisecond
or more, against a ten-millisecond budget — lands inside the measurement with no
honest way to subtract it. The binary timing itself from `main`'s first
instruction to the first flushed frame has neither problem, needs no parsing,
and is exactly the interval the budget names. What it excludes is `exec` and
dynamic loading, which is nothing on a static musl build and is already covered
from the other side by the 0.521 ms `--version` number.

Create `scripts/first-paint.sh`:

```sh
#!/bin/sh
# Gates cold start against its 10 ms budget.
#
# The binary times itself — from main's first clock read to the flush of the
# first frame — because the alternative is timing `script -qec "tug …"` from
# outside and subtracting a fork and an exec by guesswork. What this excludes is
# process spawn and dynamic loading, which the 2 ms `--version` gate covers from
# the other side.
#
# Eleven runs, median gated: a cold page cache or a scheduler hiccup on a shared
# CI runner is not a regression in tug.
#
# usage: first-paint.sh <binary>
set -eu

binary=$1
budget_us=10000
runs=11

if ! command -v script >/dev/null 2>&1; then
    echo "first-paint: no script(1); skipping" >&2
    exit 0
fi

samples=$(mktemp)
trap 'rm -f "$samples"' EXIT

i=0
while [ "$i" -lt "$runs" ]; do
    TERM=xterm-256color script -qec "$binary --debug-first-paint" /dev/null \
        | sed -n 's/^first paint: \([0-9][0-9]*\) us.*$/\1/p' >>"$samples"
    i=$((i + 1))
done

count=$(wc -l <"$samples" | tr -d ' ')
if [ "$count" -ne "$runs" ]; then
    echo "first-paint: expected $runs samples, got $count" >&2
    exit 2
fi

median=$(sort -n "$samples" | sed -n "$(((runs + 1) / 2))p")

printf 'first paint: %s us median of %s (budget %s us)\n' "$median" "$runs" "$budget_us"

if [ "$median" -gt "$budget_us" ]; then
    echo "first-paint: over budget" >&2
    exit 1
fi
```

**Interfaces:**

- Consumes: `/proc/<pid>/status` `VmHWM` (peak resident set, KiB) and

- [ ] **Step 1: Write the gate**

Create `scripts/idle-budget.sh`:

```sh
#!/bin/sh
# Gates the two budgets a parked shell has to hold: 10 MiB resident and no CPU
# at all.
#
# `--debug-keys` is the idle build — it opens a terminal, decodes keys, and sits
# in `poll` with no provider, no config file and no history. A loop that starts
# busy-waiting accrues ticks here, and that regression is invisible to every
# other gate in this repo.
#
# VmHWM rather than VmRSS because the budget is a ceiling, and a peak that has
# since been paged out is still a peak that happened.
#
# Requires Linux: /proc is where both numbers live. Skips itself elsewhere
# rather than pretending to pass.
#
# usage: idle-budget.sh <binary>
set -eu

binary=$1
rss_budget_kb=10240
park_seconds=5

if ! command -v script >/dev/null 2>&1; then
    echo "idle-budget: no script(1); skipping" >&2
    exit 0
fi
if [ ! -r /proc/self/status ]; then
    echo "idle-budget: no /proc; skipping" >&2
    exit 0
fi

state=$(mktemp -d)
capture=$(mktemp)
trap 'rm -rf "$state" "$capture"' EXIT

# A fifo held open, so the shell has a stdin that never closes and never speaks.
# Without it `script` sees EOF at once and the process leaves before it parks.
mkfifo "$state/stdin"
TERM=xterm-256color script -qec \
    "env XDG_STATE_HOME=$state $binary --debug-keys" /dev/null \
    <"$state/stdin" >"$capture" 2>&1 &
harness=$!
exec 9>"$state/stdin"

# The shell is a child of `script`, not of this script. Find it by name rather
# than guessing at pids.
pid=""
waited=0
while [ "$waited" -lt 50 ]; do
    pid=$(pgrep -P "$harness" -x tug 2>/dev/null || true)
    [ -n "$pid" ] && break
    sleep 0.1
    waited=$((waited + 1))
done

if [ -z "$pid" ]; then
    echo "idle-budget: the shell never started" >&2
    cat -v "$capture" >&2
    exec 9>&-
    exit 2
fi

sleep "$park_seconds"

if [ ! -r "/proc/$pid/status" ]; then
    echo "idle-budget: the shell did not survive its park" >&2
    cat -v "$capture" >&2
    exec 9>&-
    exit 2
fi

rss_kb=$(awk '/^VmHWM:/ { print $2 }' "/proc/$pid/status")
ticks=$(awk '{ print $14 + $15 }' "/proc/$pid/stat")

# Ctrl+D: the graded end-of-input, which on an empty draft is how a shell is
# meant to be left.
printf '\004' >&9
exec 9>&-
wait "$harness" || {
    echo "idle-budget: the shell did not exit cleanly" >&2
    cat -v "$capture" >&2
    exit 1
}

printf 'idle: %s KiB peak (budget %s KiB), %s CPU ticks over %ss (budget 0)\n' \
    "$rss_kb" "$rss_budget_kb" "$ticks" "$park_seconds"

status=0
if [ "$rss_kb" -gt "$rss_budget_kb" ]; then
    echo "idle-budget: over the RSS budget" >&2
    status=1
fi
if [ "$ticks" -ne 0 ]; then
    echo "idle-budget: the shell used CPU while idle" >&2
    status=1
fi
exit "$status"
```

### Task 3: The leak gate — a thousand interactions under DebugAllocator

The roadmap's exit criterion, verbatim: *leak-free under DebugAllocator through
a scripted 1,000-interaction session*. `src/main.zig` names this task in the
comment where it hands the shell `std.heap.smp_allocator`.

**Files:**
- Modify: `src/main.zig` — a `leak_checking` constant, `debug_allocator`,
  `sessionAllocator`, `reportLeaks`, the `.shell` arm, and the test block
- Create: `scripts/soak-session.sh`
- Modify: `.github/workflows/ci.yml`

**Interfaces:**
- Produces: `fn sessionAllocator() std.mem.Allocator` — in Debug the file-scoped
  `std.heap.DebugAllocator(.{})`; in every release mode `std.heap.smp_allocator`,
  unchanged.
- Produces: `fn reportLeaks() u8` — in Debug, `deinit`s that instance and
  returns 1 on `.leak`; in release, returns 0 without touching anything.
- Produces: `const leak_checking = builtin.mode == .Debug`.
- Consumes: `--provider mock`, `--mock-fault`, `--mock-cadence` from Phase 5,
  `/theme` and `/config` from Phase 10, and `tmux` for the resizes `script(1)`
  cannot deliver.

- [ ] **Step 3: The allocator swap**

In `src/main.zig`, above `pub fn main`:

```zig
/// A shell may run for hours, so a release build gets `smp_allocator` and pays
/// nothing for bookkeeping it will never read. A Debug build gets the
/// bookkeeping, because the roadmap's leak gate is a 1,000-interaction session
/// under exactly this allocator, and a gate needs a nonzero exit to fail on.
const leak_checking = builtin.mode == .Debug;

var debug_allocator: std.heap.DebugAllocator(.{}) = .init;

fn sessionAllocator() std.mem.Allocator {
    return if (leak_checking) debug_allocator.allocator() else std.heap.smp_allocator;
}

/// Nonzero when the session leaked. Called once, on the way out of `main`, and
/// only after everything the session owns has been released.
fn reportLeaks() u8 {
    if (!leak_checking) return 0;
    return switch (debug_allocator.deinit()) {
        .leak => 1,
        .ok => 0,
    };
}
```

In the `.shell` arm, change the allocator argument from `std.heap.smp_allocator`
to `sessionAllocator()` — replacing the comment above it with a pointer to the
helper — and make the arm report rather than tail-return:

```zig
        .shell => {
            // … the four `resolvePath`/`userPath`/`themesDir` calls, unchanged …
            try shell.repl.run(sessionAllocator(), io, stdout, .{
                // … the setup literal, unchanged …
            });
            const leaked = reportLeaks();
            if (leaked != 0) {
                var stderr_buffer: [128]u8 = undefined;
                var stderr_file: std.Io.File.Writer = .init(.stderr(), io, &stderr_buffer);
                try stderr_file.interface.writeAll("tug: the session leaked memory\n");
                try stderr_file.interface.flush();
                std.process.exit(leaked);
            }
        },
```

The `return` in front of `shell.repl.run` goes away: the leak check has to run
on the success path, and a session that failed has an exit code already.

- [ ] **Step 6: The soak script**

Create `scripts/soak-session.sh`. `tmux` rather than `script(1)` because the mix
the roadmap names includes resizes, and a resize needs something outside the
process that can change the pty's window size while it runs — which is exactly
what `tmux resize-window` is.

```sh
#!/bin/sh
# The roadmap's leak gate: a thousand interactions, one Debug process, zero
# leaked bytes.
#
# The mix is the one the phase TODO names — typing, editing, submits, mock
# streams including the fault modes, resizes, theme switches, commands —
# because a leak lives in whichever path nobody drove. The faults are in the mix
# for the same reason: `midstream_error` commits a partial block and
# `oversized_chunk` grows the tail, and both are allocation paths a happy stream
# never takes.
#
# tmux rather than script(1): a resize needs something outside the process that
# can change the window size while it runs, and script(1) has no way to.
#
# The binary must be a Debug build — that is the one running DebugAllocator and
# exiting nonzero on a leak. A ReleaseSmall binary passes this vacuously.
#
# usage: soak-session.sh <binary>
set -eu

binary=$1
interactions=1000

if ! command -v tmux >/dev/null 2>&1; then
    echo "soak-session: no tmux; skipping" >&2
    exit 0
fi

# tmux starts the pane in its own working directory, so a relative path would
# resolve against the wrong place.
case "$binary" in
    /*) ;;
    *) binary="$PWD/$binary" ;;
esac

state=$(mktemp -d)
config=$(mktemp -d)
capture="$state/capture"
socket="$state/tmux.sock"
trap 'command tmux -S "$socket" kill-server 2>/dev/null || true; rm -rf "$state" "$config"' EXIT

mkdir -p "$config/tug/themes"
: >"$capture"

tm() { command tmux -S "$socket" "$@"; }

fail() {
    printf 'soak-session: %s\n' "$1" >&2
    printf -- '--- capture (tail) ---\n' >&2
    tail -c 4096 "$capture" | cat -v >&2
    exit 1
}

tm new-session -d -x 100 -y 30 \
    "env TERM=xterm-256color COLORTERM=truecolor \
         XDG_STATE_HOME=$state XDG_CONFIG_HOME=$config \
         $binary --provider mock --mock-cadence instant >>$capture 2>&1"

# One interaction is one thing a user could do. Five per round, so the loop runs
# a fifth of the total.
rounds=$((interactions / 5))

round=0
while [ "$round" -lt "$rounds" ]; do
    # 1 — type, edit, submit. ctrl+w kills the word, so what is submitted is
    # shorter than what was typed: the buffer has been both grown and shrunk.
    tm send-keys -l "soak $round scratchword"
    tm send-keys C-w
    tm send-keys Enter

    # 2 — a multiline draft abandoned rather than sent, which is the path that
    # allocates and then throws the allocation away.
    tm send-keys -l "first"
    tm send-keys C-j
    tm send-keys -l "second"
    tm send-keys C-c

    # 3 — a command, through the registry and the block writer.
    case $((round % 3)) in
        0) tm send-keys -l "/keys" ;;
        1) tm send-keys -l "/config" ;;
        2) tm send-keys -l "/help" ;;
    esac
    tm send-keys Enter

    # 4 — a theme switch, which frees the previous theme's file bytes.
    if [ $((round % 2)) -eq 0 ]; then
        tm send-keys -l "/theme light"
    else
        tm send-keys -l "/theme dark"
    fi
    tm send-keys Enter

    # 5 — a resize, alternating between a width the tail wraps at and one it
    # does not.
    if [ $((round % 2)) -eq 0 ]; then
        tm resize-window -x 40 -y 12
    else
        tm resize-window -x 100 -y 30
    fi

    round=$((round + 1))
done

tm send-keys -l "/quit"
tm send-keys Enter

waited=0
while tm has-session 2>/dev/null; do
    [ "$waited" -ge 180 ] && fail "the long session never ended"
    sleep 1
    waited=$((waited + 1))
done

# Every fault mode, one Debug process each. A fault is a stream shape rather
# than an interaction, which is why these run after the count above rather than
# inside it.
for fault in midstream_error oversized_chunk split_utf8 empty stall firehose; do
    env TERM=xterm-256color XDG_STATE_HOME="$state" \
        script -qec "$binary --provider mock --once --mock-fault $fault --mock-cadence instant" \
        /dev/null >>"$capture" 2>&1 \
        || fail "the $fault run did not exit cleanly"
done

grep -q 'the session leaked memory' "$capture" && fail "the session leaked memory"
grep -Eqi 'panic|reached unreachable|segmentation fault' "$capture" && fail "the session crashed"

printf 'soak-session: %s interactions plus every fault mode, no leaks, no crash\n' "$interactions"
```

```zig
/// The three invariants the decoder has to hold against any byte string,
/// including ones no terminal would ever send: it never panics, it always
/// terminates, and it never emits more events than it was given bytes.
///
/// `@setRuntimeSafety(true)` is already on the decoder's own scope, so a bounds
/// or cast error in `ReleaseSmall` is a trap the fuzzer sees rather than
/// undefined behaviour it does not.
fn decodeOne(_: void, smith: *std.testing.Smith) anyerror!void {
    var input: [256]u8 = undefined;
    const len = smith.slice(&input);

    var scratch: [512]u8 = undefined;
    var decoder: Decoder = .init(&scratch);
    decoder.feed(input[0..len]);

    var emitted: usize = 0;
    while (decoder.next()) |_| {
        emitted += 1;
        try testing.expect(emitted <= len);
    }
    _ = decoder.flushPending();
}

test "fuzz: the decoder survives arbitrary bytes" {
    try std.testing.fuzz({}, decodeOne, .{ .corpus = &.{
        // Seeds, so a fuzzing session starts from shapes that mean something
        // rather than from noise: every branch of the state machine, once.
        "\x1b[A", // legacy cursor up
        "\x1bOP", // SS3, F1
        "\x1b[13;5u", // kitty CSI-u, ctrl+enter
        "\x1b[200~pasted\x1b[201~", // bracketed paste
        "\x1b[200~\x1b[A\x00\x1b[201~", // a paste that has to be sanitized
        "\x1b", // the lone escape, and its deadline
        "\xe4\xb8\xad", // a multi-byte codepoint, whole
        "\xe4\xb8", // and truncated
        "\x1b[999999999999999999;1m", // a parameter that has to saturate
        "\x1b[", // an unterminated sequence
        "\x1b_a very long unknown sequence that has to be swallowed to its cap",
    } });
}
```

```sh
#!/bin/sh
# Every row of the terminal matrix that a machine with no terminal emulator can
# fill in: a bare pty, the same pty inside tmux, a TERM that promises nothing,
# and NO_COLOR.
#
# What this asserts is degradation, not capability. A pty is not a terminal
# emulator and cannot answer the kitty or DECRQM probes, so the interesting
# claim is Phase 1's probe-hygiene item: an unanswered probe degrades to
# "unsupported" inside its budget and never hangs startup. It used to hang,
# which is carried item 1 and the reason this gate exists.
#
# The four emulator rows — kitty, alacritty, wezterm, ghostty — are not
# scriptable here and are recorded as unrecorded in docs/terminal-matrix.md.
#
# usage: terminal-matrix.sh <binary>
set -eu

binary=$1

if ! command -v script >/dev/null 2>&1; then
    echo "terminal-matrix: no script(1); skipping" >&2
    exit 0
fi

capture=$(mktemp)
trap 'rm -f "$capture"' EXIT

fail() {
    printf 'terminal-matrix: %s\n' "$1" >&2
    printf -- '--- capture ---\n' >&2
    cat -v "$capture" >&2
    exit 1
}

# `--caps` must answer inside the probe budget on a terminal that answers
# neither query. Five seconds is two orders of magnitude of headroom over the
# 50 ms it is allowed, so a timeout here means a hang and not a slow runner.
caps() {
    if ! timeout 5 script -qec "env $1 $binary --caps" /dev/null >"$capture" 2>&1; then
        fail "--caps did not finish under: $1"
    fi
}

caps "TERM=xterm-256color COLORTERM=truecolor"
grep -q '^color  *truecolor' "$capture" || fail "COLORTERM=truecolor did not reach the colour tier"
grep -q '^kitty keyboard  *false' "$capture" || fail "an unanswered kitty probe was not reported unsupported"
grep -q '^synchronized output  *false' "$capture" || fail "an unanswered DECRQM was not reported unsupported"
echo 'terminal-matrix: bare pty, truecolor, both probes degrade'

caps "TERM=xterm-256color"
grep -q '^color  *<256-word>' "$capture" || fail "TERM=xterm-256color did not give the 256 tier"
echo 'terminal-matrix: bare pty, 256 colours'

caps "TERM=dumb"
echo 'terminal-matrix: TERM=dumb answers rather than hanging'

caps "TERM=xterm-256color COLORTERM=truecolor NO_COLOR=1"
grep -q '^color  *<none-word>' "$capture" || fail "NO_COLOR did not reach the monochrome tier"
echo 'terminal-matrix: NO_COLOR is honoured'

# Inside tmux: the fifth row of the roadmap's matrix, and the only one of the
# five this machine can produce.
if command -v tmux >/dev/null 2>&1; then
    socket=$(mktemp -u)
    out=$(mktemp)
    command tmux -S "$socket" new-session -d -x 100 -y 30 \
        "env TERM=xterm-256color $binary --caps >$out 2>&1"
    waited=0
    while command tmux -S "$socket" has-session 2>/dev/null; do
        if [ "$waited" -ge 10 ]; then
            command tmux -S "$socket" kill-server 2>/dev/null || true
            cp "$out" "$capture"
            rm -f "$out"
            fail "--caps hung inside tmux"
        fi
        sleep 1
        waited=$((waited + 1))
    done
    cp "$out" "$capture"
    rm -f "$out"
    grep -q '^size  *100x30' "$capture" || fail "tmux's window size did not reach tug"
    echo 'terminal-matrix: inside tmux, window size reaches tug'
fi

echo 'terminal-matrix: every scriptable row is green'
```

- [ ] **Step 2: `docs/architecture.md`**

Three diagrams and three sections, one each, as the phase checklist asks. ASCII
diagrams, not images — this is a repository read in a terminal.

- **The loop.** `poll({stdin, wake})` with a timeout of the next render deadline
  → decode input → drain the cross-thread queue → publish on the bus → paint if
  dirty. Name the invariant: idle is zero CPU, because `timeoutMs` returns null
  when nothing is dirty. Name the two liveness bugs Phase 5's firehose found —
  a waker that cleared its pending flag before the read, and a drain that looped
  until the queue came back empty — and that bounding the drain at `capacity` is
  what fixed the second.
- **The tail.** Committed scrollback is printed once and belongs to the terminal
  from then on; the active tail is bounded to fit on screen, erased and
  repainted every frame; one `write()` per frame, enforced by a counting writer
  in the tests. The rows a repaint moves back over are counted by the same
  function that emits them — called once with a null writer to measure and once
  with the real writer to draw — because two functions would drift, and drift
  here eats a line of the user's scrollback permanently.
- **The block model.** `user`, `assistant`, `notice`. A block finalizes, renders
  into scrollback in its final form, and leaves the tail. Append-only, exactly
  like the session files it foreshadows.

- [ ] **Step 1: Write DR-015**

Follow `docs/decisions/DR-000-template.md`. The decision: **where each budget is
measured, and by what.** Three sub-decisions are worth the record.

1. **The binary times its own cold start**, rather than emitting a marker for a
   harness to timestamp. `script(1)`'s own fork and exec is a millisecond or
   more against a ten-millisecond budget, with no honest way to subtract it; a
   self-measurement from `main`'s first clock read to the first flushed frame
   has neither problem and is exactly the interval the budget names. What it
   excludes — `exec` and dynamic loading — is covered from the other side by the
   2 ms `--version` gate. Revisit trigger: the day tug links anything
   dynamically.
2. **Debug swaps the allocator, and a leak is a nonzero exit.** The alternative
   was a build option, which is a knob for a thing that has exactly one correct
   setting per build mode. Release keeps `smp_allocator` and pays nothing.
3. **The size budget is both a ceiling and a ratchet.** The roadmap's 500 KiB is
   what v0.1 promised and stays; measured + 10 % is what v0.1 costs. Growth past
   the ratchet becomes a diff and a changelog line rather than a drift.

Record what was rejected and why: `hyperfine` around a pty for cold start; a
build option for the allocator; and a CI fuzzing job — the roadmap puts it in
v0.2, and `zig build test --fuzz` runs until interrupted, which a five-minute
wall cannot hold.

- Produces: `zig-out/release/tug-<triple>` — four binaries and a `SHA256SUMS`.

**This task does not publish anything.** It builds the artifacts and stops. The

- [ ] **Step 1: The cross-compile script**

Create `scripts/release-build.sh`:

```sh
#!/bin/sh
# Builds the v0.1 release matrix from one machine, which is a large part of why
# the roadmap's five-minute CI wall is survivable at all.
#
# Signing, checksums-as-policy and distribution channels are v0.8 scope. What
# this produces is four binaries and the sums for them, to be labelled loudly
# pre-alpha wherever they are published.
#
# usage: release-build.sh
set -eu

out=zig-out/release
rm -rf "$out"
mkdir -p "$out"

for triple in \
    x86_64-linux-musl \
    aarch64-linux-musl \
    x86_64-macos \
    aarch64-macos
do
    echo "building $triple"
    zig build -Dtarget="$triple"
    cp zig-out/bin/tug "$out/tug-$triple"
done

( cd "$out" && sha256sum tug-* >SHA256SUMS )

ls -l "$out"
cat "$out/SHA256SUMS"
```
