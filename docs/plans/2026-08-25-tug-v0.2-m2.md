# tug v0.2 «Halyard» — M2 «First light» (Phases 3–4) — Implementation Plan

> **To execute:** use the `executing-plans` skill. Steps use `- [ ]` for tracking.

**Goal:** `tug dev stream --preset anthropic "why is a tugboat rated in bollard
pull"` streams a real answer from a real endpoint, `tug dev stream --preset
ollama` does the same over plaintext loopback, and every byte of that path —
request bytes out, response bytes in, `StreamEvent`s emitted — is replayed
offline in CI from recorded fixtures with no socket open anywhere.

**Architecture:** one seam and two sides of it. `src/providers/transport.zig`
defines a `Transport`: send a request, get a head, read body bytes until zero.
`src/providers/transport/http.zig` implements it over `std.http.Client` and is
the only file in the repository allowed to open a socket.
`src/providers/fixture.zig` implements it by replaying recorded bytes and is
deliberately *outside* the confinement grep's allowance, so the gate itself
proves the offline path has no network in it. Above the seam everything is pure:
`src/providers/anthropic.zig` and `src/providers/openai.zig` are a request
builder plus a mapper each — bytes in, `tugproto.StreamEvent`s out, no IO, no
clock — and `src/providers/stream.zig` is the twenty lines of glue that pulls
bytes from a `Transport`, feeds them to the Phase-2 SSE parser, and runs a mapper
over the framed events to satisfy `tugcore.Provider` without either side knowing
which transport it got.

**Tech stack:** Zig 0.16.0 (`build.zig.zon` `minimum_zig_version`), no
dependencies. `std.http.Client`, `std.crypto.tls`, `std.json`, `std.Io`. POSIX
`sh`, `util-linux` `unshare(1)`, `valgrind`. GitHub Actions on `ubuntu-24.04`.

## Global Constraints

Copied from `.artifacts/ROADMAP.md` § v0.2 and `.artifacts/v0.2.md` § Ground
rules, § Phases 3–4. Every task's requirements implicitly include this section.

- **Confinement (DR-016).** `std.http`, `std.Io.net`, `std.net`,
  `std.posix.socket` and `std.crypto.tls` may appear only under
  `src/providers/transport` — as a *textual* prefix, so both
  `src/providers/transport.zig` and `src/providers/transport/*.zig` are
  permitted. The allowance is a ceiling, not a quota: only
  `src/providers/transport/http.zig` actually spends it, and `DR-017` says so.
  `sh scripts/no-network.sh` is the gate and runs in every task's verification.
- **`tugcore` stays freestanding.** `zig build wasm-check` stays green in every
  task. `tugproviders` may import `tugcore` (the module order is proto → core →
  providers → shell); `tugcore` must never import `tugproviders`.
- **Every stream-consuming parser** gets three things in its first commit: a
  `@setRuntimeSafety(true)` scope, a `fuzz:` test target, and a
  chunking-invariance property test. Phase 2's SSE parser has all three; the two
  mappers added here inherit the rule on their JSON payload path (Tasks 8 and 9).
- **A gate that has never fired is a decoration.** Every gate added here is
  watched to fail on purpose before it is trusted, and each task says how.
- **The canary rule.** `providers.canary.key` is planted through every auth path
  added here, and every output surface is asserted not to contain it.
  `sh scripts/canary-grep.sh` covers the checked-in half and runs in every task's
  verification.
- **Checked-in fixtures never contain credentials**, and only the response side
  is ever recorded. `testdata/fixtures/README.md` is the convention; this
  milestone adds `.head` files to it and nothing else.
- **Budgets may tighten; they never silently loosen.** A number that moves needs
  a line in `CHANGELOG.md` saying why.
- **Line endings.** `.gitattributes` pins `*.sh`, `*.zig`, `*.toml` and `*.zon`
  to LF, and marks `testdata/fixtures/` `-text` so nothing there is normalized in
  either direction. A new `.head` fixture is byte-exact CRLF and lives under that
  rule; a new shell script must be LF or `sh` rejects `set -eu\r`.
- **Never stage from WSL.** Development is Windows; `git add` and `git commit`
  run from PowerShell. WSL git rewrites every markdown file to CRLF.
- **Verification is on POSIX.** Every build and test command in this plan runs
  under WSL, with the Zig cache off `drvfs` or the build dies with
  `AccessDenied`:

  ```
  wsl.exe -e bash -lc 'cd /mnt/c/Development/VCS/VCS/tug && \
    export ZIG_LOCAL_CACHE_DIR=$HOME/.cache/tug-zig && <command>'
  ```

  Every `Run:` line below is the `<command>` half. The wrapper is not repeated.
- **CI wall clock is five minutes** and the `wall-clock` job fails the run over
  it. New PR jobs must be added to that job's `needs:` list or a failure in them
  cannot fail the run. Anything that cannot hold the wall goes to `nightly.yml`.
- **Budgets, as of the start of this milestone.** Binary 196,520 B against a

## What this milestone cannot close, and why

1. **The shell still streams from the mock.** Phase 7 is interactive wiring; the
   demo here is `tug dev stream`, a debug-build-only subcommand shaped like Phase
   8's pipe frontend. The milestone map says "in the shell (manual)", and this is
   the honest version of that: the whole stack runs, the terminal frontend is not
   yet the thing driving it. Phase 7 deletes nothing to get there — it swaps the
   `dev stream` caller for the loop's.
2. **Errors are messages, not yet a taxonomy.** Phase 4 parses an error *body*
   into a message a human can act on (Task 11). Mapping HTTP status to
   `ErrKind`, honouring `Retry-After`, and the retry engine are Phase 5. This
   milestone therefore surfaces `decode` and `transport` accurately and calls
   everything else `server` with the provider's own words attached.
3. **Auth is one environment variable, read at the call site.** The resolution
   chain — flag → env → config → `key_cmd` — is Phase 5. Task 3 reads
   `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` and nothing else, and Task 13's demo
   says so in its `--help` line.
4. **Fixtures are still handwritten.** `tug dev record` is Phase 9. Every
   fixture added here carries `capture = "handwritten"`, which is what that value
   is for.
5. **Proxies.** `std.http.Client.initDefaultProxies` exists and takes an
   `Environ.Map`; Task 3 Step 6 gives it exactly one attempt and writes the
   outcome into `DR-017` either way. What is documented rather than solved in
   both outcomes: the plaintext policy does not see through a proxy.
   `.artifacts/v0.2.md` permits exactly this — "wire through if the pinned
   compiler's std client supports them cleanly; otherwise a documented deferral
   — one line in the DR either way, no heroics".

- [ ] **Step 1: Write DR-017**

`docs/decisions/DR-017-transport-seam.md`, following the shape of
`docs/decisions/DR-000-template.md`. The argument, in the repository's voice:

> **Decision.** A `Transport` is three functions — `send` a request and get a
> response head, `read` body bytes until it returns zero, `close`. Two
> implementations: `transport/http.zig` over `std.http.Client`, and
> `fixture.zig` replaying recorded bytes. Everything above the seam — request
> builders, SSE framing, mappers, retries, the conversation — is a pure function
> of bytes, and CI drives all of it from the fixture side.
>
> **Why three functions and not a `Reader`.** `std.Io.Reader` would be the
> idiomatic return, and it is the wrong shape here: the response *head* has to
> arrive before the body, because a 401 has a JSON body that is not SSE and must
> not reach the SSE parser at all. A seam that returns only a reader forces the
> status code to travel out-of-band, and out-of-band is where cancellation and
> stall detection also want to live. Three functions keeps all three on the seam.
>
> **Why the fixture transport lives outside the socket allowance.**
> `scripts/no-network.sh` permits `std.http` under `src/providers/transport`.
> `fixture.zig` is at `src/providers/fixture.zig`, outside it, which means the
> gate mechanically proves the offline path contains no network code. Putting it
> under `transport/` would cost nothing today and delete that proof.
>
> **What this forbids.** Nothing above the seam may take an `Io`, a clock, an
> allocator it did not receive, or a socket. A mapper that needs the wall clock
> is a mapper that cannot be fixture-tested, and it is the whole reason this
> version's CI can claim to be offline.

```zig
//! The transport seam — `DR-017`.
//!
//! Three functions: send a request, read the body until it says zero, close.
//! Two implementations. `transport/http.zig` opens a socket and is the only
//! file in the repository that may; `fixture.zig` replays recorded bytes and is
//! deliberately outside the confinement grep's allowance, so the gate itself
//! proves the offline path has no network in it.
//!
//! Nothing here takes an allocator, an `Io`, or a clock. Everything above this
//! seam is a pure function of bytes, which is what lets CI drive the whole
//! provider stack from a directory of recordings.

const std = @import("std");

pub const Header = struct {
    name: []const u8,
    value: []const u8,
};

/// One request. Borrowed throughout: the caller builds it in a per-request arena
/// that outlives the response, so this type owns nothing and frees nothing.
///
/// Only POST exists in v0.2, so there is no method field. A harness that talks
/// to two chat APIs makes exactly one shape of call; a `method` field would be a
/// field with one value and a reader wondering what else it could be.
pub const Request = struct {
    url: []const u8,
    headers: []const Header = &.{},
    body: []const u8 = "",
};

/// The response head, before any body byte is read.
///
/// Three fields, and each earns its place: `status` decides whether the body is
/// SSE or an error document, `content_type` catches a proxy's HTML error page
/// before it reaches the SSE parser, and `retry_after` is the raw header value
/// because Phase 5 parses both the seconds form and the HTTP-date form and this
/// layer should not know that.
pub const Head = struct {
    status: u16,
    content_type: []const u8 = "",
    retry_after: []const u8 = "",
};

/// What a transport can fail with.
///
/// Deliberately not the user-facing taxonomy: `tugproto.ErrKind` is five
/// variants a human can act on, and mapping onto it is Phase 5's job with the
/// status code in hand. These are the failures the transport itself can
/// distinguish.
pub const Error = error{
    /// The name did not resolve, or the connection was refused or reset.
    Connect,
    /// A TLS handshake or certificate failure.
    Tls,
    /// Connect, header or read timeout — including the stall detector.
    Timeout,
    /// The stream ended in the middle of something.
    Closed,
    /// The response was not HTTP tug can follow: a redirect, headers that do
    /// not parse, an unsupported transfer encoding.
    Protocol,
    /// tug refused to make the call: plaintext to a non-loopback host, or a URL
    /// scheme that is not http or https.
    Refused,
    /// The cancel token was set.
    Canceled,
    OutOfMemory,
};

pub const Transport = struct {
    context: ?*anyopaque = null,
    vtable: *const VTable,

    pub const VTable = struct {
        /// Sends the whole request and blocks until the response head arrives.
        send: *const fn (context: ?*anyopaque, request: Request) Error!Head,
        /// Fills `buffer` with body bytes. Returns 0 at end of stream, and only
        /// at end of stream — a short read is a short read, not an ending.
        read: *const fn (context: ?*anyopaque, buffer: []u8) Error!usize,
        /// Releases everything the request holds. Safe to call twice, and safe
        /// to call after an error, which is what makes `defer t.close()` the
        /// only cleanup any caller needs.
        close: *const fn (context: ?*anyopaque) void,
    };

    pub fn send(self: Transport, request: Request) Error!Head {
        return self.vtable.send(self.context, request);
    }

    pub fn read(self: Transport, buffer: []u8) Error!usize {
        return self.vtable.read(self.context, buffer);
    }

    pub fn close(self: Transport) void {
        return self.vtable.close(self.context);
    }
};
```


```zig
//! A transport that replays a recording.
//!
//! This file has no socket in it, and its location is the proof: the
//! confinement grep (`DR-016`) permits network code under
//! `src/providers/transport`, and this is not there. The offline half of the
//! stack cannot acquire a network without moving a file, which is the kind of
//! change a reviewer notices.
//!
//! A recording is two files: `<case>.head` holds the status line and headers
//! verbatim, `<case>.sse` holds the body verbatim. `parseHead` turns the first
//! into a `transport.Head`; the second needs no parsing, because replaying it is
//! the point.

const std = @import("std");

const transport = @import("transport.zig");

pub const ParseError = error{NotHttp};

/// Parses a recorded status line and headers.
///
/// Deliberately not `std.http.Client.Response.Head.parse`: that lives behind
/// the confinement rule, and reaching for it here would put `std.http` in a file
/// whose whole argument is that it has none. Three fields is not much parser.
pub fn parseHead(bytes: []const u8) ParseError!transport.Head {
    @setRuntimeSafety(true);

    var lines = std.mem.splitSequence(u8, bytes, "\r\n");
    const status_line = lines.first();
    if (!std.mem.startsWith(u8, status_line, "HTTP/1.")) return error.NotHttp;
    if (status_line.len < 12 or status_line[8] != ' ') return error.NotHttp;

    const status = std.fmt.parseInt(u16, status_line[9..12], 10) catch return error.NotHttp;

    var head: transport.Head = .{ .status = status };
    while (lines.next()) |line| {
        if (line.len == 0) break;
        const colon = std.mem.indexOfScalar(u8, line, ':') orelse continue;
        const name = line[0..colon];
        const value = std.mem.trim(u8, line[colon + 1 ..], " \t");

        if (std.ascii.eqlIgnoreCase(name, "content-type")) head.content_type = value;
        if (std.ascii.eqlIgnoreCase(name, "retry-after")) head.retry_after = value;
    }
    return head;
}

pub const Fixture = struct {
    head: transport.Head,
    body: []const u8,
    /// Bytes per `read`. Small values are the interesting ones: a stack that
    /// only works when a whole SSE event arrives at once is a stack with a bug
    /// the network will find.
    chunk: usize = 64,
    /// Cut the stream after this many body bytes, with `error.Closed` — a pulled
    /// cable, reproducibly.
    fail_after: ?usize = null,
    /// Set by `send`. Tests assert on the bytes that went out; the request
    /// builders' goldens are what make that assertion worth making.
    captured_request: ?transport.Request = null,

    offset: usize = 0,

    fn sendErased(context: ?*anyopaque, request: transport.Request) transport.Error!transport.Head {
        const self: *Fixture = @ptrCast(@alignCast(context.?));
        self.captured_request = request;
        return self.head;
    }

    fn readErased(context: ?*anyopaque, buffer: []u8) transport.Error!usize {
        const self: *Fixture = @ptrCast(@alignCast(context.?));

        if (self.fail_after) |cut| {
            if (self.offset >= cut) return error.Closed;
        }

        const remaining = self.body.len - self.offset;
        if (remaining == 0) return 0;

        var take = @min(@min(remaining, buffer.len), self.chunk);
        if (self.fail_after) |cut| take = @min(take, cut - self.offset);

        @memcpy(buffer[0..take], self.body[self.offset..][0..take]);
        self.offset += take;
        return take;
    }

    fn closeErased(context: ?*anyopaque) void {
        _ = context;
    }

    const vtable: transport.Transport.VTable = .{
        .send = sendErased,
        .read = readErased,
        .close = closeErased,
    };

    pub fn transport(self: *Fixture) transport.Transport {
        return .{ .context = self, .vtable = &vtable };
    }
};
```

- [ ] **Step 4: Write the transport**

`src/providers/transport/http.zig`. The load-bearing details, each of which is a
decision and not an accident:

```zig
//! The one file that opens a socket.
//!
//! `DR-016` confines `std.http` and `std.crypto.tls` to this directory, and
//! `DR-017` explains why the seam above it is three functions rather than a
//! reader. Everything here is mechanical: build a `std.http.Client` request,
//! hand back the head, copy body bytes into the caller's buffer.
//!
//! Four policies live here because they cannot live anywhere else — they are
//! about the connection, not about the conversation:
//!
//! 1. **No redirects.** An API does not redirect. A redirect is a captive
//!    portal, a proxy, or a misconfigured base URL, and following it would send
//!    an API key to whoever asked. `Protocol` is the error, and the location is
//!    in the message.
//! 2. **No plaintext off the machine.** `http://` is permitted to loopback,
//!    because Ollama and LM Studio serve it there and requiring TLS on
//!    127.0.0.1 would be security theatre with a real usability cost. Anywhere
//!    else it is `Refused` unless the endpoint's config says `insecure = true`.
//! 3. **Identity encoding.** `std.http.Client` advertises gzip and deflate by
//!    default. A compressed SSE stream would frame correctly and arrive in the
//!    wrong shape, and the fix — `readerDecompressing` — buys nothing for a
//!    stream of small text deltas. Ask for identity and the question is closed.
//! 4. **Nothing happens until the first send.** The client, the certificate
//!    bundle scan and the connection are all first-use, because the roadmap's
//!    10 ms prompt budget is re-asserted in Phase 10 *with providers
//!    configured*.

const std = @import("std");

const transport = @import("../transport.zig");

pub const Options = struct {
    /// Distinct on purpose. A connect that hangs and a stream that stalls are
    /// different failures with different right answers, and a single timeout
    /// makes one of them unreportable.
    connect_ms: u32 = 10_000,
    header_ms: u32 = 30_000,
    /// Doubles as stall detection: this long with no byte is a `transport`
    /// error carrying the elapsed time. Task 4 is where it acquires teeth.
    read_ms: u32 = 60_000,
    /// Per-endpoint escape hatch for plaintext to a non-loopback host.
    allow_insecure: bool = false,
};

pub const Http = struct {
    gpa: std.mem.Allocator,
    io: std.Io,
    options: Options,

    /// Null until the first send. See policy 4 above.
    client: ?std.http.Client = null,
    request: ?std.http.Client.Request = null,
    response: ?std.http.Client.Response = null,
    body: ?*std.Io.Reader = null,

    /// The body reader's transfer buffer. Chunked transfer decoding needs
    /// somewhere to work, and 16 KiB is comfortably more than one SSE event.
    transfer_buffer: [16 * 1024]u8 = undefined,
    redirect_buffer: [1024]u8 = undefined,

    pub fn init(gpa: std.mem.Allocator, io: std.Io, options: Options) Http { ... }
    pub fn deinit(self: *Http) void { ... }
    pub fn transport(self: *Http) transport.Transport { ... }
};
```

`sendErased`, in order:

1. `std.Uri.parse(request.url)`; anything that is not `http`/`https` →
   `error.Refused`.
2. `http` and not `isLoopback(url)` and not `options.allow_insecure` →
   `error.Refused`.
3. Lazily construct the client:
   `self.client = .{ .allocator = self.gpa, .io = self.io };`.
4. Connect with the connect timeout, so it is distinct from the header timeout:

   ```zig
   var host_buffer: [std.Io.net.HostName.max_len]u8 = undefined;
   const host = uri.getHost(&host_buffer) catch return error.Refused;
   const protocol: std.http.Client.Protocol =
       std.http.Client.Protocol.fromUri(uri) orelse return error.Refused;
   const connection = client.connectTcpOptions(.{
       .host = host,
       .port = uri.port orelse protocol.port(),
       .protocol = protocol,
       .timeout = .{ .duration = .fromMilliseconds(self.options.connect_ms) },
   }) catch |err| return switch (err) {
       error.TlsInitializationFailed => error.Tls,
       error.OutOfMemory => error.OutOfMemory,
       error.Canceled => error.Canceled,
       else => error.Connect,
   };
   ```

   Passing `connection` to `request()` is also what makes connection reuse
   observable: the pool is keyed on host and port, so a second turn to the same
   endpoint finds the open connection rather than handshaking again.
5. Convert the headers, then
   `client.request(.POST, uri, .{ .connection = connection, .redirect_behavior = .not_allowed, .extra_headers = extra[0..n], .keep_alive = true })`.

   ```zig
   var extra: [8]std.http.Header = undefined;
   if (request.headers.len > extra.len) return error.Protocol;
   for (request.headers, 0..) |header, i| {
       extra[i] = .{ .name = header.name, .value = header.value };
   }
   ```

   `transport.Header` and `std.http.Header` are the same two fields in the same
   order, so `@ptrCast` would work today. Write the loop: a `@ptrCast` between
   two structurally identical types declared in different files is a bet on both
   staying that way, and one of them is not ours.
6. `request.transfer_encoding = .{ .content_length = body.len }`, then
   `request.accept_encoding = @splat(false)` with only
   `@intFromEnum(std.http.ContentEncoding.identity)` set true — policy 3.
7. `request.sendBodyComplete(body)` — takes `[]u8`, so copy the body into a
   scratch buffer the request outlives. (v0.2 request bodies are conversations:
   cap the scratch at 1 MiB and return `error.OutOfMemory` above it. `ponytail:`
   comment on the cap, upgrade path is a heap buffer sized from the body.)
8. `request.receiveHead(&self.redirect_buffer)`. A redirect surfaces here as
   `error.TooManyHttpRedirects` with `.not_allowed`; map it to `error.Protocol`.
   Everything else maps by name — `HttpHeadersInvalid`,
   `HttpTransferEncodingUnsupported` → `Protocol`; `Timeout` → `Timeout`;
   `ConnectionResetByPeer`, `EndOfStream` → `Closed`; `Canceled` → `Canceled`.
9. Store `self.body = response.reader(&self.transfer_buffer)` and return
   `.{ .status = @intFromEnum(head.status), .content_type = head.content_type orelse "", .retry_after = <header scan> }`.
   **The head's string pointers are invalidated by `response.reader`** — the std
   doc says so in as many words — so build the `transport.Head` into a
   `[256]u8` field on `Http` and slice from there. Getting this wrong is a
   use-after-free that only shows up under load, which is exactly the class of
   bug `ReleaseSafe` in CI and valgrind exist to catch, and this comment exists
   so it is caught by a reader first.

`readErased` is `self.body.?.readSliceShort(buffer)`, translating
`error.ReadFailed` through `response.bodyErr()` into `Closed` or `Protocol`, and
returning 0 on `error.EndOfStream`.

`closeErased` calls `request.deinit()` (which returns the connection to the
pool), then nulls the three optionals. Idempotent, and safe after an error.

`isLoopback` parses the URI, takes the host, and compares it against `127.`
prefix + `localhost` + `::1` — but as a *whole host*, never a prefix, which is
what the `localhost.evil.example` test is for.

### Task 4: Cancellation and stall detection

**Files:**

- Create: `docs/decisions/DR-018-cancellation.md`

**Interfaces:**
- Consumes: `http.Http` from Task 3.

  Phase 7 wires `Esc`.

- [ ] **Step 1: Write DR-018**

> **Decision.** Cancellation is an atomic flag plus `Stream.shutdown(io, .both)`
> on the connection's socket, called from the loop thread while the provider
> thread is blocked in a read. The flag alone is not enough — a thread parked in
> `read(2)` on a stalled connection checks no flags — and the shutdown alone is
> not enough, because a shutdown that lands between two reads has to be
> remembered. Both, and the bound is **100 ms from `cancel()` to the provider
> thread returning**, tested.
>
> **Why not `Io` cancellation.** Zig 0.16 has `Io.Cancelable`, `Io.async` and
> `Future.cancel`, and they are the right answer for a program built on `Io`
> concurrency. tug is thread-per-stream by roadmap decision (§ Runtime model),
> and its `Io` is `init_single_threaded` in the shell — the threads are
> `std.Thread`s the frontend owns. Reaching for the `Io` cancellation machinery
> would mean adopting its concurrency model to cancel one blocking read.
> Revisit if the frontend ever moves onto `Io.Group`.
>
> **Stall detection reuses the same mechanism.** A read timeout is a cancel
> nobody asked for: a watchdog thread notices that no byte has arrived for
> `read_ms` and calls the same shutdown, with a flag saying it was a stall so the
> error is `Timeout` with the elapsed time rather than `Canceled`. One mechanism,
> two triggers, one thing to get right.
>
> **What is not cancelled.** A request that has already delivered a `text_delta`
> keeps its partial output; cancellation ends the stream, it does not unwind it.
> That is the same line `DR-019` draws for retries, and it is drawn once.

On `Http`:

```zig
/// Set from any thread. Checked between reads, and backed by a socket shutdown
/// so that a thread already blocked in one wakes up too (`DR-018`).
canceled: std.atomic.Value(bool) = .init(false),
/// Set by the watchdog when it shuts the socket down for a stall, so the reader
/// can tell `Timeout` from `Canceled` after the fact.
stalled: std.atomic.Value(bool) = .init(false),
/// Milliseconds, from the monotonic clock, of the last byte read. The watchdog
/// reads it; the reader writes it.
last_byte_ms: std.atomic.Value(i64) = .init(0),
watchdog: ?std.Thread = null,
watchdog_stop: std.atomic.Value(bool) = .init(false),
```

`cancel()` sets `canceled`, then shuts the socket down if there is one:

```zig
pub fn cancel(self: *Http) void {
    self.canceled.store(true, .release);
    self.shutdownSocket();
}

fn shutdownSocket(self: *Http) void {
    const request = self.request orelse return;
    const connection = request.connection orelse return;
    // `stream_reader.stream` is the socket std.http.Client is reading through.
    // Shutting it down is what wakes a thread parked in that read; closing it
    // would race the pool's ownership of the fd.
    connection.stream_reader.stream.shutdown(self.io, .both) catch {};
}
```

`readErased` checks `canceled` before and after each read, stamps
`last_byte_ms`, and translates the post-shutdown read failure:

```zig
if (self.canceled.load(.acquire)) return error.Canceled;
const n = self.body.?.readSliceShort(buffer) catch |err| switch (err) {
    error.ReadFailed => {
        if (self.canceled.load(.acquire)) return error.Canceled;
        if (self.stalled.load(.acquire)) return error.Timeout;
        return error.Closed;
    },
    error.EndOfStream => return 0,
};
```

The watchdog thread, started at the end of `send` and joined in `close`:

```zig
/// ponytail: one thread per active stream, waking four times a second. tug has
/// one active stream, so this costs one thread and 4 wakeups/second. If v0.3
/// ever runs streams in parallel, a single shared watchdog over a list of
/// deadlines is the upgrade.
fn watch(self: *Http) void {
    const tick_ms = 250;
    while (!self.watchdog_stop.load(.acquire)) {
        self.io.sleep(.fromMilliseconds(tick_ms), .awake) catch return;
        if (self.watchdog_stop.load(.acquire)) return;

        const idle = nowMs(self.io) - self.last_byte_ms.load(.acquire);
        if (idle < self.options.read_ms) continue;

        self.stalled.store(true, .release);
        self.shutdownSocket();
        return;
    }
}
```

```zig
//! Transport bytes in, `StreamEvent`s out.
//!
//! The three layers of this version meet here and nowhere else: a `Transport`
//! supplies bytes, the Phase-2 `sse.Parser` frames them, and a `Mapper` — one
//! per API shape — turns a framed event into zero or more `StreamEvent`s. This
//! file knows nothing about either API and both mappers know nothing about IO,
//! which is what makes the whole stack fixture-drivable.
//!
//! **Borrowing.** Every string in an emitted event points into the parser's
//! buffer or the mapper's per-event arena, and is valid until the next call to
//! `next`. That is the same contract `tugcore.Provider` already documents, and
//! it is why the streaming path allocates nothing per delta.

/// Where a mapper puts what it produced.
///
/// Four slots because the largest real case is three: Anthropic's
/// `message_delta` carries a stop reason and a usage update, and an SSE `error`
/// event produces an err and a stop. A fixed array rather than a list because a
/// mapper that wanted to emit an unbounded number of events per SSE event would
/// be a mapper doing something wrong.
pub const Emit = struct {
    items: [4]proto.StreamEvent = undefined,
    len: usize = 0,

    pub fn push(self: *Emit, event: proto.StreamEvent) void {
        if (self.len == self.items.len) return; // ponytail: drop, see doc above
        self.items[self.len] = event;
        self.len += 1;
    }
};

pub const Mapper = struct {
    context: ?*anyopaque = null,
    /// Never fails. A mapper that cannot understand an event emits an `err`
    /// event, because that is the failure the renderer already knows how to
    /// draw — the same argument `tugcore.Provider` makes for having no error
    /// union.
    map: *const fn (context: ?*anyopaque, event: sse.ServerEvent, out: *Emit) void,
};

pub const Stream = struct { ... };
```

`next()` is a small state machine:

- `.head` — call `transport.send` with the request the caller stored, then
  branch on status. `200` → `.body`. Anything else → drain the body into a
  bounded buffer, hand it to the mapper's `errorMessage` (Task 11), emit one
  `err`, go to `.done`.
- `.body` — drain `pending` first; then `parser.next()`, mapping each framed
  event into `pending`; then `transport.read` into the read buffer and
  `parser.feed`. A read of 0 ends the stream; a read error emits `err` with
  `.kind = .transport`; a `parser.failed()` emits `err` with `.kind = .decode`.
- `.done` — `null`, forever.

`provider()` wraps `next` in the `core.Provider` shape, which requires adding
`tugcore` to `tugproviders`'s imports in `build.zig`:

```zig
const providers = b.addModule("tugproviders", .{
    .root_source_file = b.path("src/providers/root.zig"),
    .target = target,
    .imports = &.{
        .{ .name = "tugproto", .module = proto },
        .{ .name = "tugcore", .module = tugcore },
    },
});
```

### Task 7: Prompt caching, decided before it is written

**Files:**
- Create: `docs/decisions/DR-022-prompt-caching.md`

**Interfaces:**
- Produces: the rule Task 8's request builder implements. No code.

- [ ] **Step 1: Write DR-022**

> **Decision.** Two `cache_control: {"type":"ephemeral"}` markers, always, with
> no configuration: one on the last block of the system prompt, one on the last
> content block of the last *user* message. No knobs, exactly as the roadmap
> promised.
>
> **Why those two positions.** Anthropic's cache is a prefix cache: a marker
> says "everything up to here is cacheable", and a hit requires the prefix to be
> byte-identical. The system prompt is the longest stable prefix in any session
> and changes only when the harness changes. The last user turn is the boundary
> that makes turn *N+1* a cache hit on turn *N*'s whole conversation — put the
> second marker on the assistant turn instead and every hit is one turn stale.
>
> **Why no knobs.** A cache marker is either right or a rounding error, and the
> configuration surface for it — which blocks, how many, what TTL — is a
> configuration surface for getting it wrong. The number that matters is printed
> instead: `cache_read_tokens` and `cache_creation_tokens` are separate fields in
> `Usage` and separate lines in the price table (Phase 6) precisely so a user can
> see the cache working rather than being asked to tune it.
>
> **Why only Anthropic.** OpenAI's caching is automatic and server-side, with no
> request-side marker to place. `openai-compat` therefore sends nothing, reads
> `usage.prompt_tokens_details.cached_tokens` when the server supplies it, and
> reports zero when it does not — which is the honest answer for six different
> servers with six different behaviours.
>
> **The four-marker limit.** The API accepts at most four. Two is the whole
> budget spent deliberately, leaving room for tool schemas in v0.3 without
> revisiting this decision.

## As executed — what happened, and where the plan was wrong

Written after the fact. The plan was a hypothesis; this is the correction.

**Green, on 2026-08-26, under `scripts/offline.sh`:** `zig fmt --check`,
`no-network`, `canary-grep`, `zig build test` (568 tests, Debug and ReleaseSafe),
`zig build replay`, `zig build fuzz`, `zig build wasm-check`, and the whole v0.1
script suite — `first-paint`, `mock-modes`, `editor-session`, `theme-session`,
`command-session`, `exit-paths`. Binary 220,832 B against the 2 MiB ceiling.

**Gates watched to fail on purpose:** the confinement grep, twice — once
accidentally, on a doc comment in `fixture.zig` that named `std.http` while
arguing the file had none, which is exactly the case the gate's own comment says
it is watching for, and once deliberately with `git mv` of `transport/http.zig`.
The ndjson golden (one character in `clean-turn.ndjson`). The replay proof (one
character in `openai/clean-turn.sse`; it failed and named the case).

**Two shipped bugs found by writing one loopback test server**, both in the read
path, both of which would have made every stream unusable and neither of which a
fixture could have found:

- `readSliceShort` is not a streaming read. It loops until the caller's buffer is
  full, so the first token of a response would have waited behind 4 KiB of
  deltas. `readVec` was no better — it fills the body reader's own buffer first
  and reports only what reached the caller's, which for one small chunked event
  is zero. The read is now `buffered()` / `toss()` with `fillMore()` only when
  there is nothing, which is what "hand back what has arrived" actually means.
- `BodyWriter.flush` flushes the protocol output, not the BodyWriter. The test
  server looked correct and sent nothing.

Both are recorded in `DR-018`, which is where a future reader will look.

### Deviations from the plan, all deliberate

1. **Task 3, proxies: deferred, not wired.** `initDefaultProxies` wants an arena
   outliving the client and this type owns none; giving it one for a feature
   nobody has asked for is not a trade worth making. `DR-017` carries the reason
   and the ten-line fix for the day it matters. The plan allowed either outcome.
2. **Task 5, the instant-prompt gate is unchanged.** The plan wanted it
   re-asserted "with providers configured", and there is no way to configure a
   provider until Phase 6 — a config file nothing reads would be exactly the
   decoration the ground rules forbid. `first-paint.sh` still gates the cold
   path; the version of it that means something arrives with Phase 7, against a
   binary that actually links the transport.
3. **`Http.cancel`'s watchdog waits on a futex, not a sleep.** The plan had it
   sleeping out a 250 ms tick. The bound in `DR-018` is on the *thread join*, and
   a watchdog sleeping out its tick blows a 100 ms bound on its own while the
   read it was watching returned in single digits.
4. **Task 8 split at the builder/mapper line**, as the plan's own handoff
   suggested it might: `anthropic.zig` builds, `anthropic_map.zig` decodes.
5. **`Mapper` grew a second function.** `errorMessage` is on the mapper rather
   than free-standing, because `Stream`'s non-200 branch needs a per-shape
   sentence and the mapper is the only thing that knows the shape.
6. **The seam is imported as `seam`, not `transport`,** in every file with a
   `transport()` method on it. Zig will not have both names in scope.

### Not verified, and why

- **No orphaned file descriptors.** `valgrind --track-fds=yes` is the check and
  valgrind is not installed on the WSL toolchain this was developed against. The
  leak half is covered mechanically by `std.testing.allocator`; the CI job exists
  and Phase 10 points it at these tests.
- **No live endpoint.** No Ollama on the development machine, and spending
  somebody's API credit is not a thing to do without being asked.
  `docs/endpoint-smoke.md` has three empty rows saying so, and `DR-023` stays
  `proposed` because its evidence table reads from that document.

## Handoff

This plan is a hypothesis about work not yet done. Four places are the likeliest
to be wrong, and the executor's job includes saying so rather than forcing them:

1. **`Connection.stream_reader.stream.shutdown` as the cancellation lever
   (Task 4).** Both fields are public in Zig 0.16.0 and the shape is right, but
   this is the one place the plan reaches past `std.http.Client`'s intended
   surface into its internals. If it does not wake a blocked TLS read — the
   record layer may sit on a partial frame — the fallback is
   `Socket.receiveTimeout` with a short tick and a flag check between ticks,
   which trades a syscall per tick for not touching internals. `DR-018` gets the
   real answer either way, and it gets it *before* Task 13 depends on it.
2. **The response head's invalidated string pointers (Task 3, step 4, item 9).**
   The std doc says `response.reader()` invalidates them. The plan copies the two
   strings tug needs into a fixed buffer first. If that copy turns out to be
   unnecessary, deleting it is fine; if it turns out to be *insufficient* —
   because the head bytes are invalidated earlier than documented — the
   `content_type` check has to move ahead of the reader call, which changes
   `Stream`'s state machine and not just this file.
3. **The `openai-compat` fixture is a guess about six servers.** It is
   handwritten from the documented shape, and the three traps it encodes are the
   ones known to exist. Ollama in Task 13 Step 5 is the first contact with a real
   one; if it deviates, the fixture is wrong and the fix is a new fixture with
   the deviation in its `note`, not a special case in the mapper.
4. **Task 8 is the largest task here** — builder, mapper, fuzz target and two
   golden files. If it wants to be two tasks when it is being executed, split it
   at the builder/mapper line; they share no state and the interfaces block above
   already names both halves.

Next milestone is **M3 «Unbreakable-ish»** — Phases 5, 6 and 7: the error
taxonomy with retries, the model registry and conversation core, and the
interactive wiring that finally puts a real stream in the shell. It gets its own
plan, written after this one is green.
